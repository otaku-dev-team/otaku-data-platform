# 首站资产复用评估：搬了什么、搬了多少、还差什么

> 评估对象：`E:\projects\acgn-test-platform`（首站源码，FastAPI + SQLite，线上 `154.8.194.198:8000`）
> 评估时间：2026-11-01　评估方式：**只读**，逐文件清点 + 逐条比对令牌，未改动首站任何文件
> 与另两份清单的关系：见第二节。三者不冲突，覆盖的是不同层。

## 一句话结论

**数据层吃满、设计层接了一半、知识层一条没搬。**

| 资产类 | 首站体量 | 落点 | 复用率 |
| --- | --- | --- | --- |
| 数据表映射 | 13 张表 | `sync-python/src/sync/dataset/mappings/otaku.json` | **100%** |
| 几何常量 | 封面 2:3、网格 150/190 | `app-client/lib/core/theme/app_layout.dart` | **100%** |
| 颜色令牌 | 19 个色阶 + 3 个底色 | `app-client/lib/core/theme/app_theme.dart` | 47%（9 个精确对齐） |
| 设计令牌全量 | 76 个（`style.css:9-105`） | 同上 | **16%（12/76）** |
| 知识词表 | 405 条（`app/tagging.py`） | 无 | **0** |
| 资讯规则 / 收录口径 | 3 条规则 + v3 五类 | 无 | **0** |

结论不是「缺得多」，而是**三类资产的性质不同，该复用的和不该复用的要用不同标准判**：

- 数据层不复用代码、直接读结果 → 已完成，且这是全项目最成功的一笔资产复用；
- 设计层是**值搬了、体系没搬** → 补令牌即可，零风险；
- 知识层**现在不该搬代码**，但**该存档口径**，否则首站一旦改规则，我们不会知道。

## 一、评估口径：从「黑盒探测」到「白盒清点」

前十天的两份清单都是**从外面看**网站：

| 文档 | 视角 | 回答的问题 | 时间 |
| --- | --- | --- | --- |
| [`旧站能力复用清单`](旧站能力复用清单) | 只读 HTTP 接口 | 能通过接口拿什么 | 2026-10-20 |
| [`站点能力差距清单.md`](站点能力差距清单.md) | 只读 HTTP + HTML | 网站有而我们没有的页面与字段 | 2026-10-22 |

前两份的共同结论是「③ 只有 HTML 是最大的一块」——那时以为很多能力没有出口、只能抓页面。现在能直接读源码，这一层可以评到更细：**哪些逻辑根本不在库里、而在应用代码里**，比如题材同义词归一、资讯垃圾过滤、收录口径判定。

所以本文件不更正前两份的任何结论，只补它们看不见的那一层。

## 二、六类资产清册

### 2.1 数据资产：13 张表全通（唯一满分的）

`mappings/otaku.json` 已把首站的表全部接通：

| otaku 目标表 | 首站源表 |
| --- | --- |
| `works` | `contents` |
| `people` | `entities` |
| `work_cast` | `content_cast` |
| `work_studios` / `series` / `tags` | `content_studios` / `series` / `content_tags` |
| `articles` | `articles` |

线上实测：works 18,828 条、全表 618,853 行、导出 12.1 秒（记录见 [`db-intake-dataset.md`](db-intake-dataset.md)）。

**这里做对的是「不复用代码、只读结果」**：首站继续产出，otaku 读派生库。搬代码会变成两份生产，违背单点。

### 2.2 设计资产：令牌只落了 16%

首站 `app/static/style.css` 240,081 字节，`:root` 定义 **76 个令牌**，分区注释清晰（设计令牌 / 基础 / 按钮 / 表单 / 徽标 / 提示条 / 分页 / 下拉）。

| 组 | 首站定义 | 客户端状态 |
| --- | --- | --- |
| 品牌色 `--brand-50..900` | 10 档 | 搬 3 档（50 / 300 / 600） |
| 辅助色 `--accent-50..900` | 10 档 | 搬 1 档（500） |
| 文字色 `--ink-900/800/700/500/400` | 5 档 | 搬 2 档（900 / 500） |
| 底色 `--surface` `--surface-2` `--card-bg` | 3 个 | 全搬 |
| **语义色** `ok/warn/err/info/pass/fail` | 10 个（bg + fg） | **0** |
| **间距** `--space-1..12` | 9 档（8pt 刻度，注释写「全站唯一来源」） | **0** |
| **字号** `--text-xs..3xl` | 8 档（行高 1.7 绑定） | **0** |
| 圆角 `sm8 / md12 / lg16 / xl20` | 4 档 | 搬 1 档（lg），其余值硬编码 |
| 阴影 `sm / md / lg` | 3 档 | 2 档以近似值写在 `cardShadow` / `cardShadowHover` |
| **动效** `--ease` + `--dur-fast/base` | 3 个 | **0** |
| 亮底文字 `--on-bright` 系列 | 3 个 | **0** |
| 焦点环 `--focus-outline` `--focus-ring` | 2 个 | **0** |
| 详情页常量 `--detail-*` | 5 个 | 按新设计另定（详情封面 220 vs 首站 104） |

**精确对得上的 12 个**：`brand-600/300/50`、`accent-500`、`surface`、`surface-2`、`card-bg`、`ink-900`、`ink-500`、`radius-lg`、`shadow-sm`、`shadow-lg`。`app_theme.dart:5-8` 的注释直接写明出处，`posterAspect 2/3` 对应 `.work-cover-box{aspect-ratio:2/3}`，`gridMinCardWidth 190/150` 对应 `.works-grid{minmax(150px)}` + `@media(min-width:768px){minmax(190px)}`。

**代价是 333 处魔数**（`app-client/lib` 内统计）：

| 类型 | 处数 |
| --- | --- |
| `SizedBox(height\|width: 数字)` | 162 |
| `EdgeInsets.all/symmetric/only/fromLTRB` | 90 |
| `Color(0x........)` 手写 | 53 |
| `BorderRadius.circular(数字)` | 28 |

不是「没有设计系统」，是**只接了一半**——间距、字号、语义色、动效全靠各处手写。

**一处明确偏离**：首站封面占位是单档品牌色渐变 `linear-gradient(155deg, --brand-100 → --brand-300 58% → --accent-200)`；客户端 `cover_image.dart:342` 换成了自创 5 档深色（`#2E6650` 绿、`#6B3B4C` 酒红、`#584D2F` 橄榄）。首站 UI 改良方案 P0-3 要的是「同品牌色系的 5 个色相变体」——这里搬了思路、换了色系。是否回正是设计取舍，不是对错。

### 2.3 知识资产：405 条词表与三条口径，一条没搬

**词表**（`app/tagging.py`，728 行）：

| 词表 | 条数 | 作用 |
| --- | --- | --- |
| `NOISE_TAGS` | 122 | 噪音标签：平台（PC/PS5/Switch/Steam）、地区、季度、元标签（神作/经典） |
| `_TRAD_TO_SIMP` | 75 | 繁简转换 |
| `GENRE_ALIASES` | 60 | 题材同义（`SF`→`科幻`） |
| `GENRE_KEYWORDS` | 38 | 题材关键词 |
| `STUDIO_ALIASES` | 32 | 制作公司别名 |
| `_STUDIO_BRAND_BLOCKLIST` | 25 | 公司品牌黑名单 |
| `MEDIA_TAGS` | 14 | 媒介标签 |
| `SOURCE_MATERIAL_TAGS` | 12 | 原作载体 |
| `_STUDIO_SUFFIXES` | 9 | 公司后缀 |
| `_PERSON_TITLE_BLOCKLIST` | 8 | 人名混进标题的守卫 |
| `TAG_CLUSTERS` | 8 | 标签聚类 |
| `TYPE_SPECIFIC_TAGS` | 2 | 类型专属标签 |
| **合计** | **405** | |

配套的三条隐性规则，比词表本身更难重建：

1. **判定顺序**：年份 → 噪音（精确）→ 公司 → 题材 → 噪音。顺序错了会让「国产动画」被公司后缀误收。
2. **查找键** `_norm_key` = NFKC + casefold，所以 `ＳＦ` / `sf` / `癒し` / `幼馴染` 都能命中。
3. **踩过的坑**（原记录在首站 `docs/标签体系全修-交接表.md`）：`galgame` 已从噪音表移出（与题材表冲突）；`roguelike` 双写法改为「规范名 + 别名」（集合双写会导致查找键不确定）；`芳文社`/`三次元` 已从公司表移出。

**资讯过滤三条规则**（`scripts/news_filters.py`，规则说明见首站 `overview-news-junk-rules-20261025.md`）：

| 规则 | 判什么 |
| --- | --- |
| `self_op_reason` | 源站自营（按源分表，机核的核聚变/核电波/GGG/商城/会员） |
| `weekly_digest_reason` | 周报 / 行业综述——命中即拒，**不看标题里堆了哪些作品** |
| `collab_merch_reason` | 联名周边：联名标记 × 实物形态 × 没有 ACG 证据 |

配套的 `_COLLAB_ACG_SIGNALS` 强信号表**刻意不收「角色 / 动画 / 恋爱 / 偶像」这类泛词**——上线当天踩过坑：本地用例用空摘要测通过，线上文章摘要写着「她不是游戏里一个虚拟的**角色**」，泛词被当成 ACG 证据放行了。

**收录口径 v3**（`import_bangumi.py` 的 `is_acgn_game_payload()`，五类优先级）：

| 分类 | 判定 |
| --- | --- |
| galge / 视觉小说 | tags 命中 `GALGAME_TAG_RE` |
| 改编 / 联动 | 联网确认动画/漫画/轻小说原作关联，或标签命中改编系 |
| 二游 / 动漫风 | 手游/二次元/美少女/乙女/恋爱/ADV 等标签 |
| 日式 RPG / 同人独立 | RPG/冒险/奇幻/同人/独立 **+ 日系信号**（假名/日式/日本） |
| 宽泛兜底 | 宽泛 ACGN 标签且 rank ≤ 1000 |

**otaku 全仓 68 份文档搜「收录口径」零命中**——这是「为什么这部作品在库里」的唯一解释，现在没有落点。

### 2.4 组件样式：只有控制台能用，但控制台不需要

首站 `style.css` 是真组件库：`cover` 31 类、`nav` 29、`btn` 21、`tag` 11、`form` 11、`table` 5，外加 `vendor/bootstrap.min.css` 232KB。

我们两处 Web 端：

- `app-client`（Flutter）：用不上 CSS，只能对令牌；
- `backend-java` 控制台：`static/console/index.html` 698 行**单文件内联 `<style>`**，10 个 CSS 变量，全仓 0 个 `.css` 文件。

控制台是内部工具，且此前已定「能用就不动」。**结论：不搬。**

### 2.5 图片资产：多数不该搬

| 项 | 实况 | 判断 |
| --- | --- | --- |
| `static/covers/` 13MB | 作品封面 | 内容数据，走数据通道，不是资产 |
| `static/img/` 924KB | 首页/分类插图、`contents-empty.png` | 空态走 CSS 渐变即可，固定比例 PNG 反而退化 |
| 字体 | **无**（`--font-sans` 是系统栈） | 无可搬 |
| 图标 | **无 SVG、无图标字体** | 无可搬 |

### 2.6 工程资产：已延续，无需再搬

首站 `scripts/devtest.py`（288 行）的「只跑改动相关测试」思路，就是 `devkit` 的前身；otaku 把它扩成了四栈（`java` / `py` / `dart` / `self`）+ 结果缓存 + `--gate` 契约守卫。这条线已完成，不在缺口里。

## 三、已复用：三笔真正搬过来的

1. **数据层 13 表映射**——不复用代码、只读结果。全项目最成功的一笔。
2. **颜色 9 个精确值**——不是近似取色，`app_theme.dart:5-8` 逐条写明出处，连深色模式都按同色相推出。
3. **几何常量**——`posterAspect 2/3`、`gridMinCardWidth 190/150` 与首站 CSS 完全一致；断点取 600 而非 768，代码里写清了理由（对齐 Flutter 的 medium 断点）。

## 四、反哺：首站没有、我们有的

资产复用不是单向的。这几样是 otaku 反超的部分：

- `devkit` 四栈选跑 + 缓存 + `--gate`（首站只有单栈 `devtest.py`）；
- **深色模式**（首站 `:root` 只有浅色一套）；
- 21 个 Flutter 共享组件（`app-client/lib/shared/widgets/`）；
- `openapi.yaml` 机器可读契约 + `acceptance.md` §4.1 的 E9–E14 交付形态验收；
- `check-site-isolation.py` 站点隔离守卫（14KB，首站无对应物）。

## 五、结论与建议

### 该做的两件

| # | 事 | 为什么 | 成本 |
| --- | --- | --- | --- |
| 1 | 补 `design_tokens.dart` 全量令牌 | 值搬了体系没搬，333 处魔数是长期成本 | 半天，纯新增零风险 |
| 2 | `docs/` 补收录口径 v3 + 资讯规则存档 | 口径只有一个真相源（首站代码），首站一改我们不知道 | 1 小时 |

原则：**令牌只接给新代码用，333 处老的不动**。改存量是纯风险、无收益。

### 明确不做的三件

| 事 | 理由 |
| --- | --- |
| 搬 405 条词表进代码 | 我们读的是首站已归一的 `tags`，自己再实现一套会出现两套口径。只有真做「搜索语义解析」或「UGC 标签审核」时才需要，届时搬 `GENRE_ALIASES` + `GENRE_KEYWORDS`（98 条）即可 |
| 搬 `news_filters` / `import_bangumi` 等生产脚本 | 首站继续产出，搬进来会变成两份生产，违背单点 |
| 控制台换首站组件 CSS | 内部工具，能用就不动 |

### 一个需要盯的风险

知识层「现在不搬」的前提是**首站口径由首站自己演进、我们只读结果**。这个前提有一个漏洞：如果哪天 otaku 要自己补库、自己审 UGC 标签、或自己做搜索语义，就必须有一份口径的**本地快照**，否则会出现「同一部作品两边判定不同」。所以建议做的第 2 件事（存档）不只是记录，是**把唯一真相源做一个可追溯的副本**。
