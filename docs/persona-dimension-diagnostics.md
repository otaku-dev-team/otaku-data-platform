## 0. 结论先行

**不是「维度设计差」（A），是「口径」（B）**——九根轴在已知口味的人群上分得开七根，方向与幅度都符合预期；
问题集中在三处口径细节 + 一处数据缺口：

| # | 问题 | 类型 | 影响 |
|---|---|---|---|
| B1 | `pop_spread` / `era_span` **天花板效应**：11 类人里 9 类拉满 98–100 | 参考值太低 | 两根轴在雷达上恒为「顶格」，没有信息量 |
| B2 | `emotion` 的激活门槛与**基础率未归一**：小样本恒 50；大样本变成「全站平均的镜子」 | 门槛 + 归一 | 轻度用户这根轴是死的；活跃用户之间差异只有基础率噪声 |
| B3 | **中性 50 一词二义**：既是「没数据」，又是「极端值」（`exploration` 单题材、`completion` 全看完） | 语义冲突 | 界面上「最偏食」与「没数据」同分 |

## 1. 方法：为什么用构造样本

#497 原写「取一批真实样本」，但生产此刻只有 **4 个账号、0 条收藏**——没有可诊断的行为数据。

所以换一个可证伪的问法：**给一批「口味已知且刻意拉开」的用户，九维能不能把他们分开？**
这是构念效度（construct validity）：连已知差异都分不开，真实用户来了只会更糟；反过来，
如果分得开，那么「塌缩」只可能来自口径，而不是用户群体。

样本不是随手编的，三个关键分布按生产实测校准：

| 维度 | 生产实测（2026-11-08） | 样本里的做法 |
|---|---|---|
| 年份 | 80s 594 / 90s 1,338 / 00s 4,271 / 10s 7,434 / 20s 4,245 | 8 个年份档，按 decade 密度加权 |
| 热度（评分人数） | P10=23 / P25=52 / P50=147 / P75=618 / P90=2,266 | 6 档：23 / 52 / 147 / 618 / 2266 / 8000 |
| 治愈+致郁覆盖率 | 作品级 **1,445 / 17,524 = 8.25%**（治愈 1,118 : 致郁 346 ≈ 76:24） | 按 8.25% 撒，治愈:致郁 = 76:24 |
| 题材数 | 真实 `work.tags` 每部 8–12 个，但题材只有 1–2 个 | 每部「1 个题材 + 1 个噪声标签」，共 24 个题材 |

11 类人群 × 10 人，两种收藏规模（12 部 / 60 部）：偏食·机战、博爱·六边形、主流厨、冷门挖掘机、
追新党、考古党、神作党、治愈系、致郁系、完播党、仓鼠党。

> **配比这条纠正过一次**：初版按 22.3% 撒，那是 `work_tag` 表里「治愈/致郁」的**标签行数**
> 除以作品总数——一部作品常同时挂「治愈」「温馨」「萌」，行数天然是作品数的两三倍。
> 算法读的是 `work.tags` 这个 JSON 列，基础率必须按**作品**算：8.25%。
> 这个错会让情绪维看起来比真实情况好得多（密度虚高近三倍）。

**同时验证了热度分位锚点**：`PersonaDimensions.POP_ANCHORS` 的原始锚点是「P50 ≈ 129」，
我们生产实测 P50 = 147、P25 = 52、P75 = 618。把我们的分位点代进锚点表，反推的百分位与真实百分位
偏差最大 **+5**（P25 处：真实 25 → 表里 30），其余 ≤ +2.3。**锚点不需要重标**。

## 4. 根因与修法

### B1 · 两根「跨度类」维度打满（`pop_spread` / `era_span`）

参考值是绝对值：`ERA_SPAN_REF = 12` 年、`POP_SPREAD_REF = 25` 个百分位点。
在真实人群里，**随便一个看番超过 20 部的人都会超过这两个值**——因为 8 个年代档的年份标准差天然 ≈13，
6 档热度的百分位标准差天然 ≈30。

**修法（任一）**：

1. 把 REF 提到人群实测的 P75/P90（例如 `ERA_SPAN_REF = 20`、`POP_SPREAD_REF = 45`）；
2. 更彻底：改成**百分位输出**——算完原始标准差，再映射成「在全体用户中的分位」。这需要一份人群基线
   （可以离线跑批存表，也可以在线抽样），好处是永远不会有天花板。

我倾向 2，但它是「引入人群基线」这个新依赖，属于架构决定，得单独拍。

### B2 · `emotion` 的门槛与基础率 —— **已修（2026-11-08）**

原诊断（保留作记录）：

1. **门槛 `EMOTION_MIN_SAMPLE = 8`**：治愈+致郁只占作品 8.25%，12 部收藏期望命中 1 部，
   命中 ≥8 部的概率约 **0.04%**——轻度用户这根轴必然恒 50；
2. **没做基础率归一**：`50 + (healing - dark)/union × 50` 在 60 部时输出 71–87，
   反映的是**全站配比**（治愈本来就比致郁常见），不是个人偏好。

**实际改法**（`PersonaDimensions.emotion`）：

- **删掉硬门槛**，改成 4 部伪计数的收缩：`oriented = (治愈 - 致郁 + 4 × 0.528) / (并集 + 4)`。
  小样本自然回到 50，大样本才敢偏离——比「门槛 5」更平滑，也不需要第二个魔数；
- **输出改成相对基础率的偏离**：与全站同配比 = 50、全治愈 = 100、全致郁 = 0；
- 分母用**情绪标签的并集**，不用「有标签的作品数」——否则「收藏多但没几部情绪番」会被压成「偏暗」。

结果：60 部 治愈 92 / 致郁 5 / 其余 44–51；12 部 治愈 84 / 致郁 15 / 其余 47–59。
详见 §7.3。

### B3 · 中性 50 一词二义

`exploration` 在 `distinctGenres <= 1` 时返回 50，`completion` 在全 watched 时返回 50。
两处都是**用「没信号」的值去表达「极端信号」**：

- 只碰一个题材 = 最偏食的极端，却拿到 50，比随便看的人（57）还「博爱」；
- 全部看完 = 完成度 100% 的极端，却和「没有完成度数据」同分。

**处理**：

- `exploration` **已修**：`distinctGenres == 1` → 10，`== 0`（没有题材数据）才给 50。见 §7.2。
- `completion` **保留现状**：导入的 Bangumi 收藏天然全是 watched，给 100 是撒谎。
  但已写进客户端说明：**50 必须结合 `sample_size` 与收藏状态分布一起读**，不能单看数值。

### A0 · 题材白名单（当前最大的实际问题）

生产配置 `app.persona.genre-tags` 为空 → `tag_focus` / `exploration` **恒 50**。
这不是算法问题，是「仓库里没有题材分类」。两条路见 #494 的评论（A：导入数据集 `tags.kind`；B：人工白名单）。

## 6. 回归保护

`PersonaDimensionDiagnosticsTest` 已经把这些结论钉成断言：

- **方向断言**（调参不该动）：偏食 `tag_focus` > 博爱 +20、主流 `mainstream` > 冷门 +30、
  追新 `fresh` > 考古 +30、神作 `quality` > 平均 +15、治愈 `emotion` > 平均 +15、
  **致郁 `emotion` < 平均 −15**、完播 `completion` > 仓鼠 +30、偏食 `exploration` < 博爱 −20；
- **反镜子断言**：与全站配比相近的人 `emotion` 必须落在 50 ± 10
  ——修前这里是 76，测的是全站标签分布；
- **小样本断言**：12 部规模下治愈系 `emotion` 仍须 > 博爱 +15——旧门槛最致命的场景；
- **现状钉住**（改主意那天必须改测试）：全 watched `completion == 50`；
- **边界钉住**：单题材 `exploration == 10`、无题材数据 `== 50`（「偏食」与「不知道」必须分开）；
- **塌缩底线**：任何一根轴在 11 类人群上的标准差都必须 > 5。

任何人改阈值/公式，只要把某根轴改塌了，这个测试会红。

## 7. 修复记录（2026-11-08，口径版本 4 → 5）

### 7.1 先纠正一处统计口径：情绪基础率是 8.25%，不是 22.3%

初版报告用 `SELECT COUNT(*) FROM work_tag WHERE tag IN (...)` 得到 4,200 行，再除以 18,828 部作品，
得出 22.3%。**这是标签行数，不是作品数**——一部作品常同时挂「治愈」「温馨」「萌」，
按作品去重后：

| 口径 | 数值 |
|---|---|
| 有标签的作品 | 17,524 |
| 带治愈标签 | 1,118（6.38%） |
| 带致郁标签 | 346（1.97%） |
| 带任一 | 1,445（**8.25%**） |
| 治愈 : 致郁（作品级） | 76 : 24 |

算法读的正是 `work.tags` 这个 JSON 列，所以 8.25% 才是基础率。用 22.3% 会高估密度近三倍，
把「轻度用户永远拿 50」这个缺陷藏起来。第 2 节的表已按 8.25% 重跑。

### 7.2 `exploration`：单题材从 50 改成 10

```java
if (total <= 0 || distinctGenres == 0) return NEUTRAL;        // 不知道
if (distinctGenres == 1) return EXPLORATION_SINGLE_GENRE;      // 10，最偏食
```

改前「只吃机战」拿 50，比「24 个题材各看一点」（57）还像博爱；改后 10。
`== 0` 仍是 50——白名单没配、或作品全是公司/媒介标签时是「不知道」，不能判成偏食。
两条都有断言（单测 + 诊断测试）。

### 7.3 `emotion`：删门槛，改成「相对全站配比的偏离」

```java
oriented = (治愈 - 致郁 + 4 × 0.528) / (并集 + 4);   // 4 部伪计数收缩到全站配比
score = 50 ± 按偏离方向归一到 [0, 100]               // 与全站同配比 = 50
```

| 人群 | 修前（60 部） | 修后（60 部） | 修前（12 部） | 修后（12 部） |
|---|---|---|---|---|
| 治愈系 | 97 | **92** | 97 | **84** |
| 致郁系 | 9 | **5** | 10 | **15** |
| 博爱/平均 | **76** | **47** | **50** | **56** |
| 主流厨 | **75** | **46** | **50** | **54** |

三件事同时改善：普通人回到中性（不再被全站 76:24 抬到 70+）、治愈与致郁两端拉得更开、
12 部的轻度用户不再恒 50。

### 7.4 这次没动的

- **`pop_spread` / `era_span` 的天花板**（B1）：仍是 11 类里 9 类 / 8 类打满。
  改常量是一小时的事，但真正该做的是「人群分位」，那要引入离线人群基线，属架构决定。
- **`completion` 的 50 二义**（B3 后半）：保留取舍，靠客户端文案消化。
- **题材白名单**（A0）：`tag_focus` / `exploration` 在生产仍恒 50。
  **原推荐的「数据集导入 `tags.kind`」经核查不成立**：源库 `tags` 表只有 `(id, name)`
  ——映射的 `fields` 只列了 `name`，`sync-python` 的测试夹具也建的是两列；dataset 侧的
  `kind` 列是从未写入过的占位。**也就是说，手头没有任何现成的题材分类。**
  两条出路都要人拍：① 产品给一份题材分类表（或站点给 `tags` 加分类字段，映射加一行即可接）；
  ② 把这两维改成不依赖分类的口径（如「全标签集中度」）——那是语义变更，要签字，
  且在分类落地前不能声称与网站同口径。
- **称号 / 标签集中度**：`hero_*` / `persona_tags` / `rarity` 未实现，仍无法测。
