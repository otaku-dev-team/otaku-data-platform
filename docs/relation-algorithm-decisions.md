## 1. #407 作品↔作品 打分

### 1.1 召回门槛 k（共享多少才算"相关"）

- **建议**：共享标签**加权分 ≥ 1.5**（≈ 命中 1 个 genre/题材标签，或 2 个普通标签）。
- 备选 A：`k = 2`（纯标签计数，不看权重）。
- 备选 B：`k = 1`（维持现状"任意重叠即候选"，但靠 §1.2 打分区分质量）。
- 影响：k 越高候选越精、召回越少；首站毛病之一正是"任意重叠即候选"导致池子太脏。

### 1.2 权重初值

公式：`matchScore = Σ(命中标签权重) + 实体命中 + 系列命中`；同分以 `rating_value` 决胜。

- **标签**：genre / 题材类 `1.5`，普通标签 `1.0`。
  > ⚠️ **数据前提（2026-11-06 pyxz0）**：`work_tag` 只有 `tag` 文本，**没有类别维度**（`V7` 建表时没有 `tag_kind`）。
  > 在数据侧补上类别前，后端无法区分「题材标签」与「普通标签」——**不得硬编码一份题材名单**（红线）。
  > 落地路径二选一：① 初版等权 `1.0`，权重系数留 `app_config`，等 `tag_kind` 到位再切；② 等导入载荷扩字段 + 重导全量。
- **实体（同 studio / 主创）**：每命中 `+0.5`，**封顶 `1.5`**（避免主创多的老番刷分）。
- **系列**：`+1.0`（但 §4 系列去重，系列命中主要服务"同系列推荐位"，不主导混排）。
- 决胜：`rating_value` 降序；`rating_count` 见 §1.4。
- 备选：全部权重 `= 1`（等权、最简）；或 TF-IDF 式（稀有标签加权，参考 paras603）。
- 影响：权重决定"题材相似" vs "主创相似"谁主导排序。

### 1.3 reasons 结构（可解释）

- **建议（结构化 JSON）**：
  ```json
  "reasons": [
    {"type": "tag",    "value": "机战",     "weight": 1.5},
    {"type": "studio", "value": "京都动画", "weight": 0.5},
    {"type": "series", "value": "凉宫春日的忧郁", "weight": 1.0}
  ]
  ```
  前端据此渲染「因为你喜欢：机战、京都动画」，修正现有"同题材：作品自身标签"与实际命中不一致的问题。
- 备选：扁平字符串数组（不可解释权重，回退方案）。
- 影响：决定前端能展示多细的"为什么推荐"。

### 1.4 rating_count 阈值（沿用 #393）

- **建议：沿用 #393 的 `50`**。`rating_count < 50` 的作品 `rating_value` 不可信，决胜时改用「收录时间 / 热度」兜底；但**仍可凭高匹配度入候选**（不直接剔除，避免浪费长尾高匹配作品）。
- 影响：避免低样本虚高评分抢位，也不浪费长尾。

## 2. #411 series 数据结构

### 2.1 方案

- **建议 B（内嵌）**：`work` 表加 `series_id` + `series_order` 两列。覆盖 95%+ 单系列场景，迁移成本最低，反查只需 `WHERE series_id = ? ORDER BY series_order`。
- 备选 A（关系表）：`work_series(work_id, series_id, order, type)` + `series(id, title)`。支持多系列 / 跨媒介（如正片 + 外传同 franchise），但导入与查询更复杂。
- 否决 C（复用 tags）：污染标签语义、无顺序、无法去重。

### 2.2 数据来源（属数据契约变更，需 pyxz0 确认）

- **建议**：导入时从 Bangumi subject 的 `series` 字段映射（需确认 import 是否已采集该字段）。
- 影响：决定是否要动 import 管线（跨模块），故纳入三人确认。

## 3. #413 曝光 / 埋点表

### 3.1 是否引入

- **建议 B（轻量曝光）**：引 `relation_impression(work_id, related_work_id, ctx, shown_at)`，仅记**展示**、**匿名**（work 级、无用户 PII）、零合规负担。为后续 CTR 调权打底。
- 备选 A（不引）：靠人工反馈，无法量化关联质量。
- 备选 C（全埋点）：曝光 + 点击 + 转化 + 时长，P2 后期再议。

### 3.2 影响与排期

- 仅影响 P2 评估能力，**不阻塞 P0 / P1**。建议与 #413 统一服务同批落地（P2 阶段），不在当前快赢里做。
