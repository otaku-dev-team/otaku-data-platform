# 旧站能力复用清单

> 检查对象：`http://154.8.194.198:8000`（现有 Otaku 网站，FastAPI，`/openapi.json` 标题为 "Otaku · ACGN 内容平台与接口自动化测试后台"）
> 检查方式：全部为**只读**请求，未写入任何数据。
> 用途：判断新平台能从旧站直接复用什么、需要加工什么、以及哪些必须自建。

> **2026-10-20 更新**：向站主提出 18 个问题后，对方**升级了接口**（新增字段 + 开放分页 + 新增标签接口）。
> 本次更新以实测复核为准，**站主描述与实测不符之处已单独标注**。
> 初次检查时"旧站只有五个字段"的判断已被推翻，勿再引用旧结论。

## 一句话结论

站主已把封面、标签、分页三件事都补上了，**我们不需要再抓 HTML**。首期可以直接拿到封面和标签，`year` 仍是数据缺口（98.5% 为空）。代价是必须遵守对方给定的限流口径，且站点**无 SLA、接口无版本承诺**，要保留本地快照兜底。

## 一、可直接复用

| 能力 | 入口 | 实测结果 | 复用方式 |
| --- | --- | --- | --- |
| 内容列表 | `GET /api/contents?type=anime&page=1&page_size=200` | **已支持分页**，返回 `{total, page, page_size, total_pages, items}`。anime 7894 条 | **必须走分页**。不传分页参数仍是一次全量，约 11.6 MB / 25 秒，站主明确禁止 |
| 内容详情 | `GET /api/contents/{id}` | 与列表同构，字段一致 | 无需逐个拉取 |
| 搜索 | `GET /api/contents/search?q=&page=&page_size=` | 真分页，返回 `{total, page, page_size, total_pages, type, items}` | 增量同步候选 |
| **封面图** | `cover_url` 字段 + `/media/full\|thumb/cover_{N}.jpg` | 100% 有值，可直连下载。full 约 95 KB，thumb 约 26–32 KB | `cover_url` 是**站内相对路径**，须拼站点域名 |
| **标签** | `tags` 字段 | 约 **80% 有值**；空值是 `[]` 不是 `null` | 直接入库，无需反查 |
| 标签词表 | `GET /api/tags?type=anime&limit=N` | ⚠️ 返回 **dict `{type, total, items:[{name,count}]}`**，不是站主描述的裸数组；默认 `limit=30` | 取 `items`。top 混有 TV / 剧场版 / 漫画改 等**形式词**，需自行过滤 |
| 健康检查 | `GET /api/health` | `{"status":"ok","service":"acgn-test-platform"}` | 同步前存活探测 |
| 放送表 | `GET /api/schedule`、`/api/schedule/seasons` | 4 个季度共 201 条；含 `title_cn` `title_jp` `weekday` `image_url` `source_url` | 可用，但见下方风险 |

## 二、不需要了（原本要做，站主上线后省掉）

| 原计划 | 现状 |
| --- | --- |
| 抓 601 页列表页 HTML 提取 `(content_id, 封面文件)` 配对 | **不需要**。`cover_url` 已直接返回 |
| 逐标签反查还原每条的标签 | **不需要**。`tags` 已直接返回 |
| 自行对全量结果分批 | **不需要**（但仍需按 `batch_size` 分批提交给 Java） |

`cover_{N}.jpg` 的 **N = bangumi_id**，不是 `content_id`。现在 `cover_url` 已拼好、`bangumi_id` 也直接返回，
映射表彻底不需要了。**实测交叉验证通过**：`content 476` → `/media/full/cover_313852.jpg`，
与升级前抓 HTML 得到的结果完全一致。

## 三、不复用

| 项目 | 原因 |
| --- | --- |
| 年份 | 字段名为 `year`，存在但**约 98.5% 为空**（12012 部里 11995 部无年份）。站主承认是数据缺口，正在补，**现阶段不要依赖** |
| 账号体系 | `/login` `/register` `/verify/email` `/admin/*`（邀请码、角色）均为旧站自有实现，未登录访问 `/me` 会 302 到登录页。新平台自建 |
| 收藏 / 状态 / 历史 | `/contents/{id}/favorite`、`/status`、`/me/history` 等均为登录后页面表单提交，**不是 JSON API**。新平台的跨端同步本就要重做 |
| Persona / LLM 报告 | `/me/persona/*` 属旧站增值功能，与新平台数据层无关 |
| 接口自动化测试后台 | `/api/testcases`、`/api/runs`、`/api/batches` 是旧站的测试平台，与本项目无关 |
| 数据摄取接口 | `POST /api/ingest/subjects` 需 `X-Ingest-Key`，无 key 返回 401。这是**往旧站写**的方向，与我们的同步方向相反 |

## 四、使用约束（站主给定，必须遵守）

| 项 | 约束 |
| --- | --- |
| 分页 | 单次全量走 `page_size=200` |
| 并发 | 来源请求 ≤ 2；**封面下载单独限流，≤ 2 并发**，不要把图床打满 |
| 速率 | 1–2 req/s |
| 配额 | 每天 ≤ 5 万请求 |
| 超限 | 来源方做 IP 级限流，我们会收到 **429** |
| 可用性 | 长期运营，**不承诺 SLA**；接口**无版本化承诺**，可能变 |
| 授权 | **非商业用途 + 注明来源**；商业用途需先取得授权 |
| 兜底 | 站主建议本地保留全量快照，**不要把他们当唯一数据源** |

## 五、需要提前说明的风险点

| 风险 | 说明与对策 |
| --- | --- |
| **封面是相对路径** | `cover_url` 为站内相对路径，域名**必须走配置**（对方可能上 CDN）。不要硬编码 |
| **WebP 不是 bug** | `/media/full\|thumb/` 是压缩衍生图（≤1200px、≤400KB 的 WebP），路径里的 `.jpg` 只是**源文件名**不是格式声明。站主明确说**永远不会改成真 JPEG**，按 `Content-Type` 处理是对的。原始 JPEG 走 `/covers/{文件名}`，体积大 3–5 倍，不推荐 |
| **档期图是 B 站外链** | `/api/schedule` 的 `image_url` 是外链且**未本地化**，B 站防盗链或换域名就会挂。**首期不要把档期图片作为强依赖**，先用标题 + 播出时间 |
| **标签可能截断** | 实测每条标签数 `min 0 / 中位 5 / max 5`，卡在 5 整，疑似有上限。站主未提及，**待确认** |
| **标签含形式词** | `/api/tags` 的 top 是 TV / 漫画改 / 剧场版 / 原创 这类**形式词**，不是题材。按 `count` 或自建词表过滤 |
| **`/api/tags` 结构与站主描述不符** | 站主说返回 `[{name,count}]`，实测是 `{type,total,items:[...]}`，默认 `limit=30`。按实测实现 |
| **更新频率不高** | 档期 + 资讯每 4 小时（cron `17 */4`），备份每天 05:41；**作品库按周从 Bangumi 官方归档选品入库**，非实时。同步作业 4 小时或 1 天一次足够，没必要更勤 |

## 六、与既有文档的关系

本清单推翻了 [`data-contract.md`](data-contract.md) 中"来源不提供封面、年份、标签，三字段恒 `null`"
的旧结论。**封面与标签已可用，年份仍不可用**。契约第 1、2 节已同步更新。

`sync-python` 侧对应调整（已实现并通过测试）：`source.py` 改为分页拉取并按 1–2 req/s 限速，
`cleaning.py` 新增 `clean_tags` / `clean_year` / `clean_cover_url`；
文本与评分的清洗规则不受影响。
