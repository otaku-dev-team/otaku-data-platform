# 站点能力差距清单：网站有什么、我们缺什么

> 探测对象：`http://154.8.194.198:8000`（现有 Otaku 网站）
> 探测时间：2026-10-22
> 探测方式：**只读**。HTML 页面直接 GET，JSON 接口直接 GET，未写入任何数据、未调用任何 `POST`。
> 与 [`旧站能力复用清单`](旧站能力复用清单) 的关系：那份文档回答「能复用什么」，本文件回答「**网站有而我们没有的是什么**」，按页面布局与字段逐项列。两者冲突时以本文件为准——**第四节列出了 4 条需要更正的旧结论**。

## 一句话结论

网站有 **16 个页面**、详情页 **23 个字段级项目**（18 项基本信息 + 5 个内容区块），我们现在落地 **10 个**。

差距不是「数据不够」，而是三层不同性质的问题：

| 层 | 性质 | 典型项 | 能否补 |
| --- | --- | --- | --- |
| ① 链路断 | 数据已经抓到了，只是没往下游传 | **年份** | 能，改 4 处即可 |
| ② 接口没接 | 站点有结构化 JSON API，我们没消费 | **新番档期 1500 条、标签词表、真分页搜索** | 能，中等工作量 |
| ③ 只有 HTML | 站点明确**没有** JSON 出口，只在渲染自己的页面 | **原名 / 别名 / 媒介 / 话数 / 制作公司 / 放送信息 / Staff / 角色声优 / 系列 / 资讯 / 推荐** | 只能抓 HTML，或绕 Bangumi |

③ 是最大的一块，也最容易被误判成「API 坏了」。**不是坏了，是从来没出口。**

## 二、详情页字段全清单

以 `GET /contents/7`（新世纪福音战士）为样本，实测 92 KB HTML。

另有标题、简介、封面、评分四项在页头，JSON API 都有，我们也都有。

### 2.2 角色与声优

- 布局：`<li>` 列表，每项 = 角色名 + `CV` + 声优名，声优链到 `/cast/{person_id}`
- 实测：6 条（碇シンジ / 綾波レイ / 惣流・アスカ・ラングレー / 葛城ミサト / 赤木リツコ / 伊吹マヤ）
- **JSON API 无出口**，`openapi.json` 里没有任何 cast / character 接口
- 一条记录隐含两个实体：**角色**（名称，可能还含角色介绍）与**声优**（人物 ID、姓名）

### 2.3 Staff

- 布局：`<li>` 列表，每项 = 人名 + 职务
- 实测：摩砂雪（副导演）/ 鶴巻和哉（副导演）/ 庵野秀明（脚本）/ 榎戸洋司（脚本）/ 薩川昭夫（脚本）/ 磯光雄（脚本）
- **JSON API 无出口**。注意：`/cast/{person_id}` 页面同时承载声优与 Staff（人物实体是共用的）

### 2.4 系列作品

- 布局：`<h2>系列作品 · {系列名}</h2>` + 卡片列表
- 每张卡片：标题、**关系词**（续作 / 衍生作 / 同系列）、年份、评分
- 实测 4 条：Air/真心为你（续作，1997，8.9）、死与新生（衍生作，1997，8.1）、DEATH (TRUE)²（衍生作，1998，8.5）、新·EVA（同系列，1995，8.5）
- 另有「系列详情 →」链到 `/creators/{name}`（系列维度页）
- **JSON API 无出口**

### 2.5 相关资讯

- 布局：`<h2>相关资讯</h2>` + 文章卡片 + 「全部资讯 →」
- 实测：本条作品**内容为空**，只有跳转链接。说明该区块按作品关联文章，EVA 暂无关联
- 资讯数据本身存在（`/articles` 列表页有大量真实文章），但 `/api/articles` 返回 **404**，无 JSON 出口

### 2.6 相关内容推荐

- 布局：卡片列表，每张 = 评分 + 标题 + 类型 · 年份 + **推荐理由**
- 推荐理由实测形态：`同题材：科幻、机战、宗教`（按共享标签生成）
- 实测 6 条
- 这是**站点实时计算的结果**，不是存储字段。我们自己有标签和评分，可以复现同样的逻辑，不需要站点出口

## 四、需要更正的历史结论

`旧站能力复用清单` 有 4 条已被本次实测推翻，**不要再引用**：

| 项 | 旧记录 | 本次实测（2026-10-22） | 影响 |
| --- | --- | --- | --- |
| `year` 覆盖率 | 约 98.5% 为空 | **非空 767 / 800 = 95.9%**（anime 均匀抽样：page 1 / 30 / 40 / 50 各 200 条） | 年份**可以立刻用**，不再是「不可依赖」，优先级从"低"提到"能马上做" |
| `tags` 覆盖率 | 空 38.5% | **非空 640 / 800 = 80.0%** | 标签可作为筛选维度 |

| 资讯 | `/api/articles` 404，只有 HTML | 接口仍是 **404**，但 `/articles` 与 `/articles/{id}` 页面**均有真实内容**（56 KB / 29 KB） | 资讯可做，代价是解析 HTML |

## 六、按性价比排的落地路径

### P0 · 年份（1 个字段，4 处改动）

链路是完整断开的，逐段确认过：

| 位置 | 现状 |
| --- | --- |
| `sync-python/src/sync/models.py` | `WorkItem.release_year` **已有** |
| `sync-python/src/sync/source.py` | **已抓** `year`，但 `to_payload()` 注释写明「只输出契约约定的 7 个字段，`release_year` 第一阶段不纳入」 |
| `backend-java` | `grep release_year` **0 处命中** |
| `work` 表 | **无该列** |
| `docs/openapi.yaml` | **无该字段** |
| `app-client` | **无该字段** |

改动：`to_payload()` 加一个字段 → `ImportItem` 加 `release_year` → `V3__add_release_year.sql` 加列 → 契约加字段 → `Work` 模型与详情页加展示。

价值：列表可显示年份、可按年份筛选，**立刻能看到内容变丰富**。

### P1 · 标签筛选 + 搜索扩面

- 标签覆盖率已达 80%，可以作筛选维度
- 站点搜索支持**标题 / 原名 / 别名 / 公司 / 声优 / 简介**六路召回；我们后端 `WorkRepository.findPage` 只有 `title LIKE`
- 原名 / 别名 / 公司 / 声优 四个字段我们还没有，所以搜索扩面要先落 P2 的字段

### P2 · 新番档期（独立新功能）

- 数据完整：1500 条，含季度、星期、放送时间/备注、作品类型、作品标签、平台、关联 `content_id`
- 需要：新表 `schedule`、同步适配器、Java 接口、客户端档期页
- 风险：`image_url` 是 B 站外链且未本地化，**不要把图片当强依赖**；`work_tags` 是斜杠字符串

### P3 · 详情页富字段（原名 / 别名 / 媒介 / 话数 / 制作 / 放送信息 / Staff / 角色声优 / 系列）

只有两条路：

1. **抓 HTML 详情页**——1.8 万条要打 1.8 万次请求，站点实测 42% 的页会断连、慢页超 32 秒，按 1–2 req/s 限速要跑约 3 小时以上，且要处理板块结构变化
2. **用 `bangumi_id` 走 Bangumi 官方 API**——`bangumi_id` 我们 100% 有值，Bangumi API 有完整的 infobox（原名、别名、话数、媒介、放送开始）、`staff`、`characters`、`persons`、`related`。**这条路更干净，且与 `sync-python` 已有的档案来源（`--source bangumi`）是同源数据**

建议走第 2 条。**推荐**和**系列**两边都能算，不必依赖站点。

### P4 · 资讯

`/api/articles` 404，只能解析 HTML（`/articles` 56 KB、`/articles/{id}` 29 KB）。站点资讯 4 小时更新一次。性价比中等，建议排在档期之后。

## 七、复现方式

```bash
SITE=http://154.8.194.198:8000
UA='-H "User-Agent: otaku-data-platform-sync/0.1.0"'

# 接口清单（105 个路径）
curl -s "$SITE/openapi.json" | python -c "import sys,json;d=json.load(sys.stdin);[print(p,list(d['paths'][p])) for p in sorted(d['paths'])]"

# 详情页（HTML，含 14 项基本信息 + 4 个内容区块）
curl -s "$SITE/contents/7" -o detail.html

# 档期（1500 条）
curl -s "$SITE/api/schedule?limit=5"

# 标签词表
curl -s "$SITE/api/tags?type=anime&limit=5"

# 实体页
curl -s "$SITE/cast/1"
curl -s "$SITE/studios/GAINAX"
curl -s "$SITE/articles/1"
```

注意：必须 `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy`，否则 curl / httpx 走本地代理连不上站点。站点单页超时给到 60–150 秒。
