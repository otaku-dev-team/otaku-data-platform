# 数据契约（草案）

> 状态：**草案 · 待评审**。由 Python 负责人于阶段 0 起草，用于锁定"作品身份、来源映射、字段与更新规则"。
> 本文不替代三人协商；标注 **待确认** 的条目须经 Java、Flutter 负责人确认后再实现。
> 所有数据来源均为 2026-10-19 对现有网站的**只读实测**，样本见 [`samples/stage0-sample.json`](samples/stage0-sample.json)。
>
> **第一阶段实现以 [`stage1-minimal-contract.md`](stage1-minimal-contract.md) 为准**（10 个字段、仅 4 个必填）。本文是完整草案，含后续阶段才用到的字段与规则；两者冲突时，第一阶段以前者为准。
> 来源站的实测结论与限流约束见 [`旧站能力复用清单`](旧站能力复用清单)。

## 1. 来源事实（实测结论）

源站：`http://154.8.194.198:8000`，接口文档 `/docs`，OpenAPI `/openapi.json`。

| 项 | 实测结果 |
| --- | --- |
| 作品总量 | 12012 条（anime 7894 / comic 1428 / game 1464 / novel 1226） |
| 返回字段 | `id`、`title`、`type`、`summary`、`rating` + `cover_url`、`tags`、`year`、`bangumi_id` |
| 字段缺失率 | `id`/`title`/`type`/`summary`/`rating`/`cover_url`/`bangumi_id` 为 **0%** |
| 部分缺失 | `tags` 约 **38.5%** 为空（1125 条跨页均匀抽样；空值是 `[]` 不是 `null`）；`year` 非空约 **95.9%**（2026-10-22 复核，旧记录「98.5% 为空」已作废） |
| 来源不提供 | 仅来源更新时间 `source_updated_at` |
| `/api/contents` | **支持可选分页** `?page=1&page_size=200`；`page_size` 硬上限 500；不传分页参数才是一次返回全量 |
| `/api/contents/search` | 同样真分页，返回 `{total, page, page_size, total_pages, type, items}` |
| `/api/tags` | 标签词表，返回 `{type, total, items: [{name, count}]}`；`total` 是返回条数，不是词表总数 |
| summary 长度 | 最短 6 字，中位 209 字，最长 7225 字；668 条超过 500 字 |
| 同类型重名 | anime 内 55 组（如「铁臂阿童木」×3、「灌篮高手」×2） |
| 跨类型同名 | anime 与 comic 之间 **341 组**（如「航海王」既是动画也是漫画） |

> **2026-10-20 更新**：来源方按我们的提问升级了接口，新增 `cover_url` / `tags` / `year` / `bangumi_id`
> 四个字段并开放可选分页。本文件第 1 节与第 2 节中"来源不提供封面、年份、标签"的旧结论**已作废**，
> 详见 [`旧站能力复用清单`](旧站能力复用清单)。

由此得出三条约束，直接影响下文规则：

1. **封面与标签不再恒为 `null`**。anime 抽样中 `cover_url` 100% 有值、`tags` 约 80% 有值，
   客户端的占位方案从"必做项"降级为"兜底项"，但仍必须保留（来源随时可能缺值或接口回退）。
2. **重名不是边缘情况，是常态**。341 组跨类型同名意味着按标题去重必然误合并。
3. **必须走分页且遵守限流**。来源方明确要求 `page_size ≤ 200`、并发 ≤ 2、1–2 req/s、
   每天 ≤ 5 万请求；一次拉全量现在约 11.6 MB / 25 秒，属于被禁止的用法。

## 2. 作品 Work

Java 侧权威记录，占据 ID；只有 Java 写新项目业务库。

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `work_id` | string | 否 | Java 生成的内部标识。样例里的 `W0xx` 仅为占位 |
| `work_type` | enum | 否 | `anime` / `comic` / `game` / `novel` |
| `title` | string | 否 | 来源标题原文，不做跨类型转换 |
| `summary` | string | 是 | 见第 6 节清洗规则 |
| `cover_url` | string | 是 | 来源已提供，但为**站内相对路径**，同步方须拼上站点域名。**建议后续迁移到自有存储**，见第 7 节 |
| `release_year` | int | **可空** | 来源字段名为 `year`，非空约 **95.9%**（2026-10-22 复核，旧记录「98.5% 为空」已作废）。有值时才填，**不得为缺失记录填 0** |
| `tags` | string[] | 是 | 约 **38.5%** 为空（空值是 `[]`）。⚠️ 该站点的 `[]` **无法区分**"明确无标签"与"未录入"，适配器统一按未提供（`null`）处理，见第 6.3 节与 `stage1-minimal-contract.md` 第 4.4.3 节 |
| `main_rating` | object | 是 | 见第 4 节 |
| `created_at` / `updated_at` | datetime | 否 | Java 维护 |

## 3. 来源映射 SourceRecord

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `source` | string | 否 | 当前唯一取值 `otaku_site` |
| `source_id` | string | 否 | 原站作品的 id，字符串存储避免数值歧义 |
| `source_url` | string | 是 | 来源详情页或 API 地址 |
| `fetched_at` | datetime | 否 | 本次成功采集时间 |
| `source_updated_at` | datetime | 是 | 来源不提供更新时间，恒 `null` |

唯一约束：**`(source, source_id)`**。同一来源记录重复导入不得生成第二条作品。

## 4. 来源评分 SourceRating

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | number | 原始分值，不做归一化 |
| `scale` | string | 取值域说明，当前来源为 `0-10` |
| `source` | string | 评分来源标识 |

规则：

- **缺失值不等于 0 分**。无评分时 `main_rating` 为 `null`，客户端不得显示 0.0。
- 来源评分与个人评分是两套数据，互不相干。
- 评分尺度（当前是 0-10 还是 0-100）**待确认**，须在 `_scale` 明确后再做跨源比较。

## 5. 去重与身份判定

| 判定 | 结论 |
| --- | --- |
| 同一 `(source, source_id)` 再次出现 | 同一作品，更新，不新增 |
| 标题相同、来源 id 不同 | **不同作品**，各自保留 |
| 标题相同、`type` 不同 | **不同作品**（341 组跨类型同名的现实约束） |
| 标题带季数/篇章后缀差异 | **不同作品**，不得并入无后缀条目 |
| 某次抓取中某条记录未出现 | **不代表删除**，不删除已有作品 |

草案采用的最小判定链：先用 `(source, source_id)` 精确命中；未命中则新增。首期**不做基于标题的模糊合并**。

## 6. 清洗与更新规则

### 6.1 文本清洗（Python 负责）

- `summary` 中的 `\r\n` 统一规范化为 `\n` 后入库，交由客户端按段落渲染。
- 保留 `[简介原文]` 等来源自带标记，不在同步层擅自截断或删除。
- 空字符串一律转为 `null`。
- 不在同步层做摘要截断；超长文本由客户端自行折叠。

### 6.2 字段更新原则

| 场景 | 处理方式 |
| --- | --- |
| 来源值非空且已有值不同 | 更新该字段 |
| 来源值为空 / 缺失 | **不覆盖**已有可靠内容，记为未变化 |
| 本次抓取未出现该记录 | 不动任何字段 |
| 来源不可用的整次抓取 | 中止并记录，不写入部分结果，不清空现有数据 |
| 校验不通过的单条记录 | 记为 `rejected`，不影响同批次其他记录 |

### 6.3 三态字段语义

`cover_url` / `release_year` / `tags` 用 `null` 表示"来源未提供"（不覆盖已有内容），
用空数组 `[]` 表示"明确无标签"（可据此清空）。

**但这个站点的实际口径是：`tags` 为空时一律给 `[]`，从不给 `null`。** 实测 anime 跨页
均匀抽样 1125 条中 38.5% 为 `[]`，其中多数是"还没录入"而不是"确认没有标签"——站点
本身不区分这两种情况。

因此第一阶段的做法是：**`otaku_site` 适配器把 `[]` 按"未提供"处理（转 `null`）**，
即首期实际只会出现 `null` 这一种空态。理由是如果把 `[]` 当"明确无标签"，站点一次缺数据
就会把平台已有标签清空且不可回滚。三态语义仍保留在契约里：后续接入能区分两种空值的站点
时无需改契约，只去掉适配器里那条转换。

细节见 [`stage1-minimal-contract.md`](stage1-minimal-contract.md) 第 4.4.3 节。

## 7. 个人数据（引用，非本文主责）

由 Java 与 Flutter 承担，此处仅登记与数据契约相关的约束：

- 收藏记录按 `user_id + work_id` 唯一。
- 观看状态枚举 `want` / `watching` / `watched`，加入收藏后状态可为空，取消收藏同时删除状态。
- **作品数据同步不得覆盖账号、收藏、个人状态。** 两个方向的同步互不干扰。

## 8. 同步批次结果（Python 负责产出）

| 字段 | 说明 |
| --- | --- |
| `batch_id` | 本次批次标识，用于重跑与追踪 |
| `source` | 来源标识 |
| `counts` | `{inserted, updated, unchanged, rejected}` |
| `errors` | 逐条错误，含 `source_id`、错误码、错误信息 |
| `started_at` / `finished_at` | 批次起止时间 |

要求：同一批次重跑结果一致（幂等）；`rejected` 记录可定位并重提。

## 9. 来源使用约束（站主给定，同步方必须遵守）

| 项 | 约束 |
| --- | --- |
| 分页 | 单次全量须走 `page_size=200`。不分页的全量请求约 11.6 MB / 25 秒，**被明确禁止** |
| 并发 | 来源请求 ≤ 2；封面下载单独限流，≤ 2 并发 |
| 速率 | 1–2 req/s |
| 配额 | 每天 ≤ 5 万请求 |
| 超限后果 | 来源方做 IP 级限流，同步方会收到 **429**（须按 429 重试，不得硬冲） |
| 可用性 | 长期运营但**无 SLA**，接口**无版本化承诺** |
| 授权 | 数据可用于**非商业用途并注明来源**；商业用途需另行授权 |
| 兜底 | 来源方建议本地保留全量快照，**不要将其作为唯一数据源** |
