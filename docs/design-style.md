## 0. 一句话

**浅蓝底、白卡片、天蓝主色，按 Material 3 组装。主色只做底，不做字。**

这句话包含两个最容易搞错的地方：

1. 主色是 `#66CCFF`，不是某一档深蓝。它是整档色阶里**最亮的那两级之一**，白底上只有 1.8:1，所以只能当背景；
2. 桌面端和网站要长得像**同一个产品**，不是浏览器里一个样、装上客户端一个样。用户不存在「切换应用」的心理动作。

## 1. 主色：一个色，三个角色

品牌蓝 `--brand-400` `#66CCFF` 是站点 `:root` 注释里的原话「品牌主色（天蓝 #66CCFF 族）—— 全站主视觉」。
它在色阶里被拆成三个角色用，跟网站一样：

| 角色 | 色值 | 令牌 | 用在哪 |
| --- | --- | --- | --- |
| **做底** | `#66CCFF` | `Palette.brand400` / `AppTheme.brand` | 主按钮、顶栏强调、选中胶囊、Hero |
| **做字** | `#1C73B0` | `Palette.brand700` | 白底上的链接、分类标签、文字按钮、描边按钮 |
| **做线** | `#2A9AE0` | `Palette.brand600` | 焦点边框、进度环、`RefreshIndicator`、输入框聚焦态 |

做底时必须配深字 `--on-bright` `#0A2D42`（`OnBright.onBright`），**不能配白字**。

### 对比度实测

| 前景 | 背景 | 对比度 | 结论 |
| --- | --- | --- | --- |
| `#0A2D42` | `#66CCFF` | **7.94:1** | 主按钮 / 顶栏的正解 |
| `#FFFFFF` | `#66CCFF` | **1.8:1** | 读不出，禁用 |
| `#1C73B0` | `#FFFFFF` | **5.09:1** | 白卡片上的链接 |
| `#1C73B0` | `#F1F6FC` | **4.7:1** | 页面浅底上的链接 |
| `#2A9AE0` | `#FFFFFF` | **3.11:1** | 只够做线，不够做正文 |
| `#66CCFF` | `#0B1620`（深色底） | **8.7:1** | 深色主题里可直接当字 |
| `#1C73B0` | `#0B1620` | **3.1:1** | 深色主题里不能用 |

> 网站 `:root` 注释里写的是「11.6:1」，那是拿 `#66CCFF` 跟**纯黑**算的，不是跟 `--on-bright` 算的。
> 上面的数字是按 WCAG 2.1 相对亮度公式重算的，两者差了 3.7——照抄注释会得出「白字也行」的错误结论。

### 为什么之前错过一次

`AppTheme.brand` 一度填的是 `--brand-600`，理由是「它在色阶里更耐看、也是 link 用的那一档」。
这在单看某一屏时完全不像错：两档只差两级，都是蓝。但两端并排就能看出一个是浅天蓝、一个是中蓝。
**这种偏离只有把两端摆在一起对照才看得出来**，单端走查永远发现不了。同类错误在类型色上又犯了一次（§3）。

## 2. 色板分层：底、卡、字、语义

### 2.1 三层底色

| 层 | 色值 | 令牌 | 说明 |
| --- | --- | --- | --- |
| 页面底 | `#F1F6FC` | `Palette.surface` | 明显带蓝，不是灰白。`ColorScheme.fromSeed` 生成的 surface 偏灰，代码里显式覆盖了 |
| 次级底 | `#E6EEF8` | `Palette.surface2` | 表头、分区底 |
| 卡片 | `#FFFFFF` | `Palette.card` | |

卡片描边 `#DFE9F4`（`Palette.cardBorder`）**严格说不是令牌**：网站里没有提成变量，是 14 处直接写死的。
收进令牌是因为它已经是卡片视觉的一部分、且客户端一直在用，留一份散值反而更容易走样。

### 2.2 文字色阶

| 档 | 色值 | 用途 |
| --- | --- | --- |
| `ink900` | `#17142B` | 强调标题 |
| `ink800` | `#241F3F` | 正文默认——网站 `body` 用的是这一档，不是 900 |
| `ink700` | `#3D3759` | 次级正文 |
| `ink500` | `#6F6A8A` | 元信息、时间、来源 |
| `ink400` | `#9A95B3` | **只做装饰**（分隔、图标），网站注释明确说对比度不足，别当正文 |

### 2.3 语义色：浅底 + 深字成对

网站是成对出现的，客户端此前没有这组，红绿各页面手写（同一件事用了不同的绿）。现在只从 `Semantic` 取：

| 语义 | 底 | 字 |
| --- | --- | --- |
| ok | `#E7F8EF` | `#157347` |
| warn | `#FFF5E0` | `#855C00` |
| err | `#FDECF0` | `#C32D4D` |
| info | `#EAF7FF` | `#0F5E8C` |
| pass / fail | —— | `#157347` / `#C32D4D`（只有前景，测试结果行用） |

### 2.4 辅助色

`--accent-500` `#39C5BB`（favicon 那抹青）是**辅助**，不是第二主色。
它当前只出现在两处：封面占位渐变的尾段、`ColorScheme.secondary`。不要拿它做按钮或导航——那会让「哪个是品牌色」变得说不清。

## 3. 类型色：四个色相归谁是固定的

| 类型 | 色值 | 深浅两档 |
| --- | --- | --- |
| 动画 | `#2A9AE0`（brand600） | 浅 `brand300` |
| 漫画 | `#E8557D` | 浅 `#FFB3C7` |
| 游戏 | `#25A79C`（accent600） | 浅 `accent300` |
| 小说 | `#7C5CD6` | 浅 `#CDB4F6` |
| 未知 | `#9A95B3`（ink400） | —— |

**别按「好看」重排。** 2026-11-01 之前客户端自己配了一套（动画靛、漫画粉、游戏紫、小说青），
其中**游戏和小说跟网站正好互换**——同一部作品，网站上是青色、客户端上是紫色。

这处偏离最难发现，因为判据选错了：补令牌时统计的是「`:root` 变量的落点」，
而漫画粉 `#E8557D`、小说紫 `#7C5CD6` 在网站里是**直接写死、没提成变量**的。
「不在令牌里」不等于「没有出处」。真正的判据是**同一语义在两端的表现是否一致**，比「变量搬没搬」宽。

客户端只用一个色（图标 + 14% 透明底），所以取深档；浅档留着做渐变。

## 4. 层级语言：卡片 + 描边，不靠阴影

`cardTheme.elevation = 0`。分层靠三件事：

1. **1px 描边** `#DFE9F4`；
2. **底色差**（页面浅蓝 → 卡片纯白）；
3. **圆角**。

阴影只在两处有意义：卡片默认 `--shadow-sm`（两层叠加，肉眼几乎看不出），桌面端 hover `--shadow-lg`。
深色主题里阴影基本不可见，所以两套主题共用同一份阴影，真正的分层靠描边。

### 圆角四档

| 档 | 值 | 用途 |
| --- | --- | --- |
| `sm` | 8 | 小标签、徽标 |
| `md` | 12 | 卡片内缩略图、输入框、导航指示器 |
| `lg` | 16 | 卡片（`AppTheme.cardRadius`，布局层别名同值） |
| `xl` | 20 | 对话框 |

内层必须比外层小一档（卡片 16 / 内部封面 12），否则两层圆角贴在一起会出现一条突兀的白边。

### 顶栏跟页面同色

不是白色。白条压在浅蓝底上会切出一条明显的横缝，首页尤其突兀（顶上一条白、下面一片浅蓝）。
`surfaceTintColor: transparent` + `scrolledUnderElevation: 0` 也是为这个：Material 默认滚动时会染色，一染就不是同一个底色了。

## 5. 间距与字号

### 间距：8pt 刻度

`s1=4 / s2=8 / s3=12 / s4=16 / s5=20 / s6=24 / s8=32 / s10=40 / s12=48`。
页面左右内边距固定 `s4 = 16`，网格间距 `s3 = 12`。

### 字号：8 档，正文 14

`xs12 / sm13 / base14 / md16 / lg18 / xl20 / xxl24 / xxxl30`。
正文 `base = 14`，比 Material 默认的 16 小一档——网站全站就是 14，桌面端跟着它；手机端也确实更适合密一点的列表。

### 字号和行高是两件事

**`--text-*` 只是尺寸，没有绑定行高。** 网站的行高是各元素单独写的：正文块 1.7、标题 1.15 / 1.04 / 1.25、徽标 1.7。

所以令牌里不提供「字号 + 行高」的组合。用的时候按场景自己给 `height`，
**别为了省事硬塞一个统一值**——那会把网站本来分开的两件事又合成一件，最后要么正文太紧、要么标题太散。

## 6. 动效

| 项 | 值 | 令牌 |
| --- | --- | --- |
| 缓动 | `cubic-bezier(0.4, 0, 0.2, 1)` | `Motion.ease`（就是 Material 的标准缓出） |
| 快 | 150ms | `Motion.fast` |
| 基础 | 240ms | `Motion.base` |

图片淡入是 160ms（`CoverImage.fadeInDuration`），比 `fast` 略长：封面是内容主体，切换太急会显得闪。

## 7. 深色主题：同色相另推一套

网站只有浅色一套 `:root`，深色是客户端自己推的。原则是**同一个设计换明度，不是另做一个设计**：

| 项 | 值 | 对应浅色 |
| --- | --- | --- |
| surface | `#0B1620` | `#F1F6FC` |
| card | `#152431` | `#FFFFFF` |
| border | `#263D50` | `#DFE9F4` |
| ink | `#E6EDF5` | `#17142B` |
| inkSoft | `#93A4B8` | `#6F6A8A` |

深色下 `#66CCFF` 有 8.7:1，所以**主色可以直接当字**，不需要另找一档；反过来 `#1C73B0` 在深色底上只有 3.1:1，不能用。
这条决定了 `AppTheme.brandInk(context)` 为什么按亮度分支。

## 8. 系统取色（Android 动态取色）

开了 Material You 时，整套 `ColorScheme` 来自壁纸。这里只有一条规矩：

**品牌字色必须跟着系统的 `primary` 走**，不能固定填 `#1C73B0`。

否则会出现「底色是壁纸取的紫、字还是固定天蓝」——用户明确要求跟随系统，结果只跟了一半，比完全不跟随更怪。
实现是 `AppStyle.brandInk`（`ThemeExtension`），组件读 `AppTheme.brandInk(context)` 而不是读常量。
做成 `ThemeExtension` 而不是全局状态：组件只在 build 时读一次，主题重建时整棵树自动更新，不用订阅。

例外是 `AppTheme.brandStrong`（焦点环 / 进度环）用常量——有几处 `RefreshIndicator` 在 `_buildList(...)` 这类方法里拿不到 `context`，而它属于品牌 chrome，跟系统取色无关。

## 9. 玻璃质感（可选样式）

`AppTheme.light/dark(glass: true)` 是实验开关，不是默认外观。

打开后卡片、对话框、导航栏变半透明，`scaffoldBackgroundColor` 必须设成透明（否则那层渐变永远看不见），
模糊层由 `GlassBackdrop` 提供。组件用 `AppTheme.isGlass(context)` 判断要不要加模糊。
`AppStyle.lerp` 里 `glass` 没有中间态（`t < 0.5` 保持原值），开关不能半开。

## 10. 组件层约定

| 场景 | 用什么 | 为什么 |
| --- | --- | --- |
| 主按钮 | `primary` 底 + `onPrimary` 字 | `onPrimary` 显式覆盖成 `OnBright.onBright`，Material 默认给白字，白字压天蓝只有 1.8:1 |
| 文字按钮 / 描边按钮 | 主题级 `foregroundColor: brandText` | 默认是 `primary`（天蓝），22 个 `TextButton` 里只有两个手写了颜色，靠默认值才不会漏 |
| 输入框聚焦 | `brandFocus`（brand600）、1.6px | 对应网站 `--focus-outline: 2px solid var(--brand-600)`；Material 默认取 `primary`，换主色后会是一根淡到看不见的线。**宽度是 1.6 不是 2**，这是承接的旧值，没有留下理由——跟网站差 0.4，看不出来，也不值得为它动所有输入框。写在这里是为了让下一个人知道这处差异是已知的、不是抄漏 |
| 进度环 / `RefreshIndicator` | `progressIndicatorTheme.color = brandFocus`，页面另加 `color: AppTheme.brandStrong` | 同上，默认读 `primary`，换主色后转圈在白底上只有 1.6:1 |
| 顶栏 | 跟页面同色、无染色 | 见 §4 |
| 卡片 | elevation 0 + 1px 描边 + 圆角 16 | 见 §4 |
| 类型徽标 | `TypeColor.of()`，图标 + 14% 透明底 | 见 §3 |

### 封面占位：两档画法，语义一致

同一套占位在小海报上好看、放到整屏头图上就难看，所以按用途分开（`CoverPlaceholderStyle`）：

- **海报位**（网格卡、列表磁贴、详情小海报）：`155deg` 渐变 `brand100 → brand300(58%) → accent200` + 首字水印。
  155° 换算成 Flutter 是 `Alignment(-0.42,-0.91) → Alignment(0.42,0.91)`（方向余弦，不是像素偏移）。
  首字用 `#0A2D42` 45% 透明——是水印，不是标题。
- **头图位**（首页精选、详情沉浸头图）：深色渐变 + 极淡径向高光，**不画字**。
  六组配色全取品牌色阶深端（brand/accent 700–900），白字最低压 5.0:1。

头图**不能用海报那段浅渐变**：浅底上压白字读不出来，而头图是要给白字当背景的。
这一组是照网站色板推的、不是照抄——网站的头图位是真图，没有占位形态可取。

三种缺失状态必须能区分：没有封面（渐变 + 首字）／正在加载（纯骨架，无渐变无文字）／加载失败（与「没有封面」同款）。
失败态和「本来就没有」在视觉上不分是**契约的选择**：契约不允许出现破图，而用户该做的动作是一样的。

## 11. 已知不统一的地方（都不打算改）

这些不是遗漏，是明确留下的。改它们是纯风险、无收益：

| 项 | 规模 | 为什么不动 |
| --- | --- | --- |
| 存量魔数 | `SizedBox` 162 处、`EdgeInsets` 90 处、`Color(0x..)` 53 处、`BorderRadius.circular` 28 处 | 令牌只给新代码用。全量替换是几百处纯机械改动，翻车风险和收益完全不成比例 |
| `schedule_page.dart` 自带一套 `_CoverPlaceholder` | 1 处 | 两套画法并存，但这块归 #95（@riceyu02），不越界改 |
| 顶栏没有铺成主色实底 | 形态差异 | 网站顶栏是白底 + 天蓝点缀，客户端跟页面同色，本来就不是同一形态。**这不是偏离，别按「对齐」的名义改它** |
| 控制台 | `backend-java/static/console/index.html` 单文件内联 CSS | 内部工具，能用就不动；它不属于这套设计系统 |
| 405 条知识词表 | `app/tagging.py` | 我们读网站已归一的 `tags`，自己再实现一套会出现两套口径 |

## 12. 写新代码时怎么用

1. **数值只从 `design_tokens.dart` 取**，不写字面量。要一个间距先看 `Space`，要一个色先看 `Palette`。
2. **新增颜色先问：它是品牌色阶里的哪一档？** 如果答不上来，说明它多半不该存在——网站没有的颜色，客户端也不该新造。
3. **改主题时别动这三条**：`brand = brand400`、`brandInk`（亮 `brand700` / 深 `brand`）、`onPrimary = OnBright.onBright`。这三条互相咬合，动一个另外两个就错了。
4. **令牌不给存量用**。老的 333 处保持原样，新文件按令牌写。
