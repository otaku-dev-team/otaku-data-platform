## 2. 最小字段集

### 2.1 作品字段（第一阶段就这些）

| 字段 | 类型 | 必填 | 谁产生 | 说明 |
| --- | --- | --- | --- | --- |
| `work_id` | string | 是 | **Java** | 平台内部标识。生成方式与取值格式由 Java 决定；**客户端只当不透明字符串处理**，不得解析其结构 |
| `work_type` | enum | 是 | Python 提交 | `anime` / `comic` / `game` / `novel` |
| `title` | string | 是 | Python 提交 | 来源标题原文，不做跨类型转换，不做清洗截断 |
| `summary` | string | **可空** | Python 提交 | `\r\n` 已统一为 `\n`；**不截断**（最长 7225 字），折叠由客户端处理 |
| `cover_url` | string | **可空** | Python 提交 | 来源站相对路径已拼成绝对地址。客户端直连还是后端代理**待确认**（见第 7 节） |
| `tags` | string[] | **可空** | Python 提交 | 来源每条最多 5 个（已知截断）。`[]` = 明确无标签 |
| `main_rating` | object | **可空** | Python 提交 | `{value, scale}`，当前来源尺度 `0-10`。**缺失不是 0 分** |
| `source` | string | 是 | Python 提交 | 当前唯一取值 `otaku_site` |
| `source_id` | string | 是 | Python 提交 | 原站作品 id，字符串存储避免数值歧义 |
| `updated_at` | datetime | 是 | **Java 维护** | 记录最后更新时间 |

列表接口可只返回前 6 项 + `work_id`，详情接口返回全部（见第 5 节）。

### 2.2 第一阶段明确不纳入

| 字段 / 能力 | 不纳入的原因 |
| --- | --- |
| `release_year` | 来源约 **98.5% 为空**，站主承认是数据缺口。客户端展示不出东西，还容易误导。**不得为缺失记录填 0** |
| 系列 `series_id`、别名 `aliases`、原名 `title_original` | 来源库里有，但 **JSON API 未出口**。已向站主争取，争取到再纳入 |
| 话数 `episodes`、媒介 `media`、原作载体 `source_material` | 同上，且填充率未确认 |
| 多来源评分合并 | 第一阶段只有一个来源 |
| 封面下载到自有存储 | 需 Java 侧建文件服务，成本高；先用来源站地址 |
| 账号、收藏、观看状态 | 第二阶段范围，不在本契约 |

`release_year` 若 Java 侧想预留数据库列，可以留，但**第一阶段接口不出口、界面不展示、不参与筛选**。

### 2.3 可空规则（三条硬规则）

1. **必填只有四个**：`work_type`、`title`、`source`、`source_id`。缺任一，Java 应拒绝该条记录并返回字段级错误。
2. **可空的一律传 `null`，不传空字符串**。空字符串在入库前统一转 `null`。客户端遇到 `null` 必须走占位，不得显示 `0`、`"无"` 之类的伪值——尤其是评分。
3. **`tags` 有第三态**：`null` = 来源未提供（**不覆盖**已有值）；`[]` = 明确无标签（可据此清空）。第一阶段来源只给 `[]`，不覆盖规则仍然成立。

## 3. 唯一标识

### 3.1 两层标识，各管一段

| 层 | 标识 | 谁用 | 说明 |
| --- | --- | --- | --- |
| 平台内部 | `work_id` | **客户端唯一使用** | Java 生成。客户端所有业务（收藏、状态、跳转详情）只认它 |
| 跨系统定位 | `(source, source_id)` | **Python 与 Java 之间** | 同步作业的定位依据，Java 侧建**唯一约束** |

`source_id` 可以返回给客户端做溯源展示，但**客户端不得用它做业务判断**。

### 3.2 判定链（Java 实现，就这么一条）

```
用 (source, source_id) 精确命中
  ├─ 命中 → 更新，不新增
  └─ 未命中 → 新增
```

**首期不做任何基于标题的模糊合并。** 实测约束摆在那里：anime 内重名 55 组（「铁臂阿童木」×3）、跨类型同名 341 组（「航海王」既是动画也是漫画）。按标题去重必然误合并。

### 3.3 客户端三条禁止

1. 不得用 `title` 判定两条记录是不是同一个作品。
2. 不得解析 `work_id` 的结构或自增规律。
3. 某次列表里没出现的作品，不代表已删除——**同步不做删除**（来源方也不承诺删除语义）。

## 4. 接口链路一：Python → Java（提交 / 同步作品）

> URL 路径、鉴权头名称、DTO 与代码组织**全部由 Java 负责人决定**。本文只定语义。

### 4.1 边界

- 只有 Python 同步作业调用，走内部令牌，**客户端不得持有该密钥**。
- 分批提交，建议单批 **≤ 500 条**。
- **只有 Java 写库**；Python 不直接碰数据库。

### 4.2 请求格式

```json
{
  "batch_id": "otaku_site-anime-20261020-3a9f1c",
  "source": "otaku_site",
  "items": [
    {
      "source_id": "476",
      "work_type": "anime",
      "title": "街角魔族 2丁目",
      "summary": "第一行\n第二行",
      "cover_url": "http://154.8.194.198:8000/media/full/cover_313852.jpg",
      "tags": ["日常", "搞笑"],
      "rating": { "value": 7.8, "scale": "0-10", "source": "otaku_site" }
    }
  ]
}
```

`batch_id` = `{source}-{类型}-{日期}-{内容指纹}`，指纹为排序后 `source_id` 集合的哈希。
**同一批输入重跑得到同一个 `batch_id`**（已实测验证）。

### 4.3 响应格式

```json
{
  "batch_id": "otaku_site-anime-20261020-3a9f1c",
  "counts": { "inserted": 97, "updated": 3, "unchanged": 0, "rejected": 0 },
  "errors": [
    { "source_id": "9999", "code": "TITLE_REQUIRED", "message": "标题为空" }
  ]
}
```

逐条结果只需四类计数 + 失败明细。成功条目不必逐条回传。

### 4.4 幂等与重试

| 场景 | 期望行为 |
| --- | --- |
| 同一 `batch_id` 重跑 | **结果一致，不得重复入库**（验收 E1/E2） |
| 同一 `(source, source_id)` 重复提交 | 更新，不新增 |
| 网络错误 / 超时 / 5xx / 429 | Python **重试**（带退避） |
| 4xx（含 401、400） | **不重试**，直接记为未送达并落盘报告 |
| 缺内部令牌 | Python **提交前直接失败**，不发请求 |

### 4.5 错误处理

见第 6 节统一格式。链路一额外约定：

- 单条记录校验失败 → 该条 `rejected`，**不影响同批其他记录**。
- 整批格式错误 → 整批拒绝，Python 记为未送达。
- 来源整次抓取异常 → Python **中止本次，不写入部分结果，不清空现有数据**。

## 5. 接口链路二：Flutter → Java（列表与详情）

> URL 路径、DTO、鉴权实现**由 Java 负责人决定**。本文只定语义与字段。

### 5.1 作品列表

**请求参数**（名称由 Java 定，语义如下）：

| 参数 | 说明 |
| --- | --- |
| `type` | 可选，`anime`/`comic`/`game`/`novel`；不传 = 全部 |
| `q` | 可选，标题关键词模糊搜索 |
| `page` / `page_size` | 分页，`page_size` 建议**上限 50** |

**响应**：

```json
{
  "total": 1200,
  "page": 1,
  "page_size": 20,
  "total_pages": 60,
  "items": [
    {
      "work_id": "...",
      "work_type": "anime",
      "title": "街角魔族 2丁目",
      "cover_url": "http://.../cover_313852.jpg",
      "tags": ["日常", "搞笑"],
      "main_rating": { "value": 7.8, "scale": "0-10", "source": "otaku_site" }
    }
  ]
}
```

列表**不返回 `summary`**——最长 7225 字，会把列表响应撑爆。

### 5.2 作品详情

按 `work_id` 取。返回第 2.1 节的**全部字段**（含 `summary`、`source`、`source_id`、`updated_at`）。

`work_id` 不存在 → `404` + `WORK_NOT_FOUND`。

### 5.3 客户端展示约定

- `cover_url` 为 `null` → 显示占位图，不得用空白或报错占位。
- `main_rating` 为 `null` → **不显示评分**，不得显示 `0.0`。
- `summary` 为 `null` → 显示"暂无简介"；非 `null` 时按 `\n` 分段渲染。
- `tags` 为 `[]` → 不渲染标签区。

### 5.4 分页与排序

- 分页参数与响应字段名由 Java 定，`total` 必须返回，否则客户端无法判断末页。
- 排序：第一阶段**只要求稳定**（同一查询多次返回顺序一致），具体排序规则由 Java 定。

## 6. 统一错误响应

两条链路共用：

```json
{ "error": { "code": "WORK_NOT_FOUND", "message": "作品不存在" } }
```

**第一阶段只需要这几个错误码**：

| code | HTTP | 含义 | 客户端/Python 该怎么做 |
| --- | --- | --- | --- |
| `UNAUTHORIZED` | 401 | 未认证或令牌无效 | **不重试**；Python 记为未送达 |
| `BAD_REQUEST` | 400 | 请求格式或参数错误 | **不重试**；修正后重发 |
| `WORK_NOT_FOUND` | 404 | 作品不存在（仅链路二） | 客户端提示后返回列表 |
| `BATCH_TOO_LARGE` | 413 | 单批条数超限 | Python 自动拆批后重发 |
| `RATE_LIMITED` | 429 | 限流 | **重试**，带退避 |
| `INTERNAL` | 500 | 服务端错误 | **重试**，带退避 |

链路一的逐条错误（如 `TITLE_REQUIRED`）走 4.3 节的 `errors` 数组，不进这个信封。
