# otaku-data-platform（跨平台作品平台）

> 本文档描述项目规划方向，相关功能与架构为预期目标，不代表已经实现。

## 项目介绍
构建一个跨平台作品平台，帮助用户发现、查询和管理感兴趣的作品。平台整合公开来源的作品数据，通过后端提供统一的数据与业务服务，并由跨平台客户端提供完整的用户体验。
项目采用模块化设计，当前规划包括：
Flutter 客户端：面向用户的浏览与交互体验。
Java 业务后端：业务逻辑、数据管理与 API 服务。
Python 数据服务：公开数据源接入、数据处理与同步。
最终目标是交付一个能够真实运行、模块协同、可测试、可演示并能持续扩展的产品

## 核心价值
帮助用户发现、查询和管理作品，通过整合不同来源的数据改善作品信息的获取与使用体验。

## 产品构想
用户通过 Flutter 客户端使用平台，Java 后端提供业务能力，Python 数据服务负责作品数据的获取、整理和同步。

## 技术架构
- 客户端：Flutter
- 后端：Java + Spring Boot
- 数据服务：Python
- 数据库：MySQL
- 模块间通过 API 协作

各技术模块按上述职责配合；具体实现细节（如框架选型、部署方式、接口格式）由各模块负责人调研确定，本文档不把尚未决定的实现细节写死。这是当前初步方向，负责人可提出改进建议；涉及其他模块的变更需团队协商。

## 主要功能设想
- 作品浏览与搜索
- 作品详情
- 个人作品管理
- 持续扩展的数据服务能力

> 以上为规划方向，用于明确产品目标，不冒充已经实现的功能。登录、收藏、追番状态及其他进阶功能后续安排。

## 三人分工
- **Flutter 负责人**：负责 App 的界面、交互、客户端架构和 API 接入。
- **Java 负责人**：负责业务后端、数据库、业务 API 和数据持久化。
- **Python 负责人**：负责公开数据源接入、数据处理、同步与相关测试。

各负责人自主调研技术方案、拆分任务并决定模块内部实现。不得擅自改变共享接口、模块边界或影响其他成员的设计。

## 第一阶段目标
打通最小端到端闭环：Python 从至少一个合规数据源获取并整理作品数据，通过 API 提交给 Java 后端；Java 保存并提供查询 API；Flutter 调用真实 API 展示作品。完成基础联调、测试和运行说明。

第一阶段具体任务和技术实现由各负责人自行规划，团队共同确认数据模型、API 契约和验收标准。

## 协作规则与任务管理
本项目使用 GitHub Issues 和 GitHub Projects 进行任务管理与团队协作。
- **GitHub Issues**：记录开发任务、技术讨论、问题反馈及相关结论。
- **GitHub Projects**：集中查看和跟踪任务进度，通过 `Todo`、`In Progress` 和 `Done` 等状态了解任务所处阶段。
- **协作流程**：成员可通过 Issues 参与讨论、补充建议，并根据实际进展更新任务状态。
- 使用功能分支和 Pull Request 协作；影响其他模块的接口或架构变更须提前协商。
- 不提交密钥；AI 生成的代码必须实际检查和测试。
