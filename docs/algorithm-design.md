## 1. 定位与原则

- **纯规则、可解释、按站烘焙**：不引模型、不照搬网站未定口径、不写 `otaku` 硬编码。
- 第一阶段体验纵深的核心算法，**优先级最高**，可能需要跨模块多人投入。
- 客户端只做渲染与本地展示优化，**打分与画像聚合在服务端**。

## 3. 画像（#401 聚合 + #375 渲染）

> **状态（2026-11-06）**：B1 聚合 + B2 端点已实现（`GET /api/me/profile`），契约见
> [`openapi.yaml`](openapi.yaml) 的 `PersonaProfile`。原草案的 `/api/profile` 与 camelCase 字段
> **已按下面两条理由改掉**；三人如要调整权重初值或字段，改的是实现里的常量与 schema，回滚成本低。

聚合维度与权重（纯规则，可解释）：

| 信号 | 权重 | 说明 |
| --- | --- | --- |
| 浏览 | `1.0 + 0.25 × (次数-1)`，封顶 `2.0` | 反复看是强兴趣，但别让刷页把画像刷歪 |
| 收藏 `want` / `watching` / `watched` | `2.0` / `3.0` / `4.0` | 意图强度递增；`status` 为空按 `want` |
| 点评 7–10 分 | `+3.0`（有正文 `+0.5`） | 正面证据 |
| 点评 5–6 分 | `+1.5`（有正文 `+0.5`） | 中性偏正 |
| 点评 1–4 分 | `-1.5` | **负反馈**，不折成 0 |
| 只写正文不打分 | `+0.5` | 愿意表达仍是信号，但不进评分分布 |

- 标签按作品标签数**均摊**（`weight / tagCount`），避免标签多的作品主导画像；
- 权重按维度**归一化到 -1–1**（各自除以绝对值最大者），最强项恒为 ±1；
- `sample_size` = 参与聚合的行为行数，客户端据此判断「口味是否还在形成」；
- `recent_active` = 最近 30 天有行为的作品 id，倒序去重，最多 20；
- 软删作品的行为**仍计入**（偏好是历史事实）；
- 实时聚合、不落画像表（首版行数远小于上限）。

**评分倾向的两路来源（#495）**：评分不等于「写没写过点评」——用户在 Bangumi / B 站导入的收藏
自带评分。口径是**自己打的分优先，没有才回落到 `work.rating_value`**（来源站均分）：
`rating_scale` 为 `0-10` / `1-10`（含空值）时归一成 1–10 的整数分，其他量纲**不猜**（返回缺失）。
同一作品按 `work_id` 去重——三路 `UNION ALL` 会让它出现多次，不去重则均值变成
「这个作品我点开过几次」的函数。当前生产 94,443 部作品有 0–10 评分，所以这条一上线，
「只导入收藏、不写点评」的用户评分轴就不再是空的。

读取契约（**已实现**）：

```
GET /api/me/profile            ← 不是 /api/profile
Authorization: Bearer <token>
→ {
     "type_weights": { "anime": 1.0, "game": 0.4 },
     "tag_weights":  { "机战": 1.0, "后宫": -0.6 },
     "rating_tendency": { "mean": 8.0, "count": 2, "dist": [0,0,0,0,0,0,1,0,1,0] },
     "recent_active": [ "W-xxx", "W-yyy" ],
     "sample_size": 12,
     "dimensions": {
       "tag_focus": 50.0, "exploration": 50.0, "mainstream": 63.2, "pop_spread": 41.7,
       "quality": 72.7, "era_span": 38.4, "fresh": 25.0, "emotion": 55.6, "completion": 66.7
     },
     "generated_at": "2026-11-06T06:00:00Z"
   }
```

**九维（#494，2026-11-08 接线）**：`dimensions` 由 `PersonaDimensions`（纯函数，口径对齐网站
`persona.py` / `DIMENSION_VERSION=4`）计算，0–100、50 中性，**数据不足给 50 不给 0**——
0 在雷达图上是一个凹角，看起来像「这方面很弱」，实际是「还没数据」。九个键**恒存在**。

输入按**作品**去重（同一作品可能同时出现在浏览/收藏/点评三路），`status` 从收藏行补全，
评分沿用 #495 的口径（自己的分优先、没有才回落来源站均分）。

⚠️ **`tag_focus` / `exploration` 目前恒为 50**：这两维要一份「哪些标签算题材」的白名单，
而仓库里没有权威分类——`work.tags` 把题材、公司、角色混在一个 JSON 数组里，数据集 `tags` 表
虽然建了 `kind` 列但映射只导了 `name`。白名单通过 `app.persona.genre-tags` 配置（默认空）；
在它落地前，这两维不参与区分度判断。硬编码一份名单等于替来源定义分类，#467 已否过一次。

**区分度怎么验**：见 [`persona-dimension-diagnostics.md`](persona-dimension-diagnostics.md)（#497）——
11 类已知口味人群 × 两种收藏规模的构造样本，逐维看能不能分开；结论与优化顺序都在那篇，
回归断言在 `PersonaDimensionDiagnosticsTest`（无数据库依赖，秒级）。

**两条对草案的修正**：

1. **路径改为 `/api/me/profile`**：`AuthFilter` 只拦 `/api/auth/me`、`/api/me`、`/api/me/**`，
   `/api/profile` 不在其中——照草案挂上去就是**匿名可读**，而画像是个人行为数据。
   改鉴权白名单会打破「个人数据都在 `/api/me` 下」的惯例，改路径成本更低。
2. **字段改 snake_case**：契约通篇 snake_case（Jackson 策略），草案里的 `typeWeights` 是笔误；
   落进 `openapi.yaml` 时以实际序列化结果为准。

空画像的语义：没有任何行为时 `type_weights` / `tag_weights` 为**空对象**、
`rating_tendency.mean` 为 **null**、`sample_size` 为 0——不返回一堆 0.0（那会被读成「平均 0 分」）。

## 4. 规则引擎（#373 原型 → #402）

从 #373 落地的规则（可解释、加权求和）：

1. **标签/类型协同**：基于画像 `tag_weights` / `type_weights` 对候选打分。
2. **评分倾向**：偏好高均分或特定分布（结合 `rating_count` 阈值，低票不计入倾向）。
3. **时效/新鲜度**：近期、未看作品加权。
4. **站内共现**：协同过滤式（同看/同标签用户的交集作品）。

输出：候选作品带 `score`，截断 Top-N。

### 落地范围（2026-11-06，#402）

| 规则 | 状态 | 说明 |
| --- | --- | --- |
| 1 标签/类型协同 | ✅ 已实现 | 候选 = 画像权重最高的 8 个正标签，每标签取评分最高 200 部；负权重标签扣分 |
| 2 评分倾向 | ✅ 部分 | 用「作品评分质量 × 0.3」参与排序，只对 `rating_count >= 50`（或票数未知）生效；**未**按用户 `rating_tendency.mean` 做个性化偏移 |
| 3 时效/新鲜度 | ⏸ 不做 | 「近期」对补番型用户是负信号（老番同样值得推），且没有曝光数据能验证加权是否有效。等 #413 的曝光表落地后再用数据决定 |
| 4 站内共现 | ⏸ 不做 | 当前活跃用户个位数，共现矩阵没有统计意义。用户量到百级再评估 |

**为什么先做 1+2**：这两条只依赖单人行为，不需要任何跨用户数据，今天就能算对；
3/4 要么需要数据验证、要么需要用户量，做了也只是「规则齐全但没人能证明它对」。

打分公式（`RecommendService`）：

```
score = Σ(命中标签的画像权重) + 类型权重 × 1.0 + 评分质量 × 0.3
```

同分按作品评分降序。`score` 最后按本次结果最高分**归一化到 0–1**。

## 5. 推荐 API（#402）

**已实现**（2026-11-06）：

```
GET /api/me/recommend?limit=20      ← 不是 /api/recommend（同画像的理由：鉴权）
Authorization: Bearer <token>
→ {
     "items": [
       {
         "work": { ...WorkSummary... },
         "score": 1.0,
         "reasons": [
           { "type": "tag",  "value": "机战", "weight": 1.0 },
           { "type": "type", "value": "anime", "weight": 0.5 }
         ]
       }
     ],
     "cold_start": false,
     "generated_at": "2026-11-06T06:00:00Z"
   }
```

- `score` 是**组内归一化**的相对分（除以本次最高分），不是跨请求可比的绝对分；
- `reasons` 最多 3 条、按权重降序，`weight` 是画像里的归一化权重（不是最终得分）；
- `limit` 默认 20、上限 50，超出截断不报错；
- 冷启动（画像为空）返回全站高分榜，`cold_start: true`、各项 `reasons` 为空、`score` 为 0。
