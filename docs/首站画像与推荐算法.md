## 2. 画像怎么算

**数据源三合一**，先跨源归一再去重：

- Bangumi 公开收藏（`fetch_user_collections`，公开 API，上限 1000 条）
- 站内收藏 / 标注
- B站追番

**9 个维度**（`persona.py:104`）：题材垂直、探索广度、大众度、冷热跨度、高分率、年代跨度、追新度、情绪取向、完成度。

阈值不是拍脑袋的，每条都带实测记录：

```
mainstream  >= 93   → 主流厨     # 85 时近四成账号撞同一称号；93 = 全站前 7%
mainstream  <  35   → 冷门挖掘机
exploration >= 68   → 博爱       # 60 时约三成人命中
tag_focus   >= 63   → 偏食
58 <= quality < 75  → 口碑党     # 50 时近八成人都带，等于没区分度
quality     >= 75   → 神作党
want/seen   >= 1.5  → 仓鼠       # 想看远多于看过
```

最多取 3 个特征，顺序固定：**热度 → 口碑 → 口味/行为**。顺序是有讲究的——口味特征排在口碑后面会被「高分」槽整批吃掉，深度用户就体现不出来。

称号五层命中：组合毒舌 → 极端值成就 → 簇×特征主表 → 身份兜底 → 回退拼接。每一层都要有兜底，否则会出现「谁都不带特征」。

**画像本身是纯规则**，不联网、确定性可复现。LLM 只用来写「长评文案」，不参与任何判定。

分享卡走 `encode_card` / `decode_card`，名片编成一个 token，不需要登录也能看。

## 3. 推荐怎么选

入口 `build_user_home_picks`（`persona.py:2343`）。

### 两道闸决定用哪套口径

```python
stale = site_total >= profile_total * 1.5 and site_total >= profile_total + 10
# 两个条件都满足，才弃用画像、改走站内实时口味
```

比例闸挡小涨幅，基数闸挡小基数下的百分比抖动。刚同步完 Bangumi 的用户不会因为站内多收藏两三部就翻推荐。

### 总口味 / 近期口味双象

- 近期 = 90 天内有过动作的作品
- 不足 3 条 → 回落取最近 3 条
- 近期命中的题材权重 **2.0 倍**
- **浏览记录不进算法**，注释原话：「浏览≠喜欢，噪音大于信号」

### 打分就一行

```python
score = sum(weights[tag] for tag in matched) * 10 + effective_rating(rating, count)
排序：(-score, -effective_rating, content_id)
```

命中的题材数主导（×10），评分做同分加权。低票作品的评分在排序里按 **0** 算，不给任何加成。

### 四条硬规则

| 规则 | 效果 |
|---|---|
| 避雷标签一票否决 | `tags & avoided` 直接跳过，「宁可少推，不推雷」 |
| 只推有题材标签的 | 无标签无法证明命中 |
| 已收藏 / 已标注剔除 | |
| 系列去重 | 按标题前缀聚类，同系列只占一个推荐位，取最早的一部（推荐位要能从第一季看起） |

标签必须先归一：`expand_genre_names` 把「日常系」「致郁系」「体育竞技」展开成站内真实标签名。不归一就会精确对撞落空，避雷会**静默失效**。

### 兜底

没有可用信号 → 回落站长口味 `list_home_recommendations`，保证推荐位不空。

「近期口味」还有一层兜底：新用户动作太少时取最近 N 条，否则永远算不出近期。

## 4. 照做时最容易漏的五点

1. **评分必须两套口径**。展示用 `rating_shown`（人数不足出「--」），排序用 `effective_rating`（低票按 0）。只有一套就会出现「1 个人打 10 分」既占榜首又被加权推上首页——我们 2026-11-02 刚踩过这个（#370）。
2. **近期口味权重 2.0，但浏览不算信号**。实现成本几乎为零，比上模型稳。
3. **避雷一票否决 + 系列只占一位**。各几行代码，体验差别很大。
4. **标签归一**。不做归一，避雷静默失效、推荐静默落空，且很难发现。
5. **每层都要兜底**。画像没特征、推荐没命中、没有近期动作——每一层不兜底就是一片空白或同一批人撞同一称号。

## 5. 我们要用，还缺什么

我们后端现在只有 `work` / `collection` / `tag`，**没有画像表，也没有推荐**。

要接这套，主信号只有 `collection`，缺的正好两样：

- **`rating_count`**——判断评分可不可信，没有它排序会被假高分污染（#370 已在排）
- **负向信号**——避雷 / 低分 / 抛弃。首站是靠 Bangumi 的个人评分和「抛弃」状态做的，我们目前没有

另外我们的 `collection` 只有 `updated_at`、没有版本号，并发改同一个收藏时服务端只能「后写的赢」——做画像前得先解决这个（见 `docs/开源参考与可借鉴项.md` 收藏同步那节）。
