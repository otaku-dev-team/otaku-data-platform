## 环境

| 组件 | 实际使用 |
| --- | --- |
| 后端 | `localhost:8080`，接 MySQL 3310 的联调库（237 部作品） |
| 桌面端 | Windows，`flutter run -d windows`，窗口 1680×1200 |

## 逐条结果

### 1. A 的账号可登录两端，平台内新增的收藏两端可见

两端条数与内容一致。

- 手机登录 A → 收藏页 3 条：`铁臂阿童木`（未设状态）、`NHK15个动画短片`（在看）、`零度战姬Vibration`（在看）
- 桌面打开收藏页：同样 3 条，顺序、状态、相对时间都对得上
- 服务端 `GET /api/me/collections` 返回 `total: 3`，与前两者一致

**判定：通过。**

### 2. 手机收藏 → 桌面端刷新可见

- 手机在 `铁臂阿童木` 详情页点「收藏」→ 按钮变「已收藏」，出现「未设状态」选择器，SnackBar「已加入收藏」
- 接口确认服务端多了一条（`status: null`）
- 桌面端打开收藏页：第一条就是它，显示「4 分钟前」

**判定：通过。** 桌面端不需要重启，重新进收藏页即拉到新数据。

### 3. 桌面端改状态 → 手机端刷新可见

- 桌面把 `铁臂阿童木` 改成「在看」→ 接口 `status: watching`
- 手机收藏页下拉刷新 → 该条显示「在看」

**判定：通过。**

### 4. 取消收藏 / 清除状态 → 另一端按规则显示

两个方向都测了：

- 桌面「清除状态」→ `status: null`，手机刷新后显示「未设状态」（**不是**消失，收藏还在）
- 桌面在详情页点「已收藏」取消 → 手机刷新后该条整条消失，列表从 3 条变 2 条

**判定：通过。** 「收藏」和「状态」是两个独立维度，清除状态不会删除收藏。

### 5. B 无法读写 A 的数据；切账号不残留

- 手机退出 A → 收藏页立刻变回「登录后可以跨端同步收藏」引导，**不残留 A 的列表**
- 手机登录 B → 收藏页「还没有收藏」，A 的 3 条一条都看不到
- 服务端层面此前已验（PR #44 的联调用例 C5）：B 读 A 收藏过的作品仍是 `collected: false`

**判定：通过。**

### 6. 退出再登录数据保留；多设备会话符合约定

- 手机退出 A 再登回来 → 2 条收藏原样在（第 4 条里被取消的那条自然不在）
- 手机退出期间，桌面端 A 的会话一直可用（期间还在桌面端改了状态、取消了收藏，全部成功）
  → 退出**只结束当前会话**，不踢其他端（C9）

**判定：通过。**

### 7. 并发、重复请求、超时

- **重复请求**：在详情页快速连点收藏按钮两次，只发出 1 次 `PUT`，服务端 1 条记录，界面无异常
- **并发修改**：两个会话同时 `PATCH` 同一作品（`want` / `watched`），两个都 200，
  最终值是最晚写入的那个（`updated_at` 晚 68ms 的 `watched`）；客户端重进页面显示「看过」
- **超时**：用 `iptables -A OUTPUT -d 10.0.2.2 -j DROP` 阻断到后端的流量后点取消收藏 →
  10 秒连接超时，弹出「请求超时，请稍后重试」，**按钮仍是「已收藏」**，没有误报成功

**判定：通过。** 失败不产生「已同步」的假象（C7）。

### 8. 过期界面改状态（C11）——服务端实测 + 客户端代码路径核对

> 补测于 2026-10-22 02:55。这一条不在 `flutter-lead-plan.md` §8 的 7 条里，
> 但它是 `acceptance.md` 的 C11，此前一直没人验。

**场景**：界面上还显示着「已收藏」，但那一条其实已经被另一端取消了。
此时用户在里面改观看状态，客户端如果顺手发 `PUT` 补建一条，就等于**悄悄把用户删掉的收藏又加回来**。

**服务端实测**（后端 `localhost:8080` + MySQL 3310，账号 `alice`，作品 `W-x7t0ep51fkdyzkr`）：

| 步骤 | 请求 | 实际响应 |
| --- | --- | --- |
| 1 | `PUT /api/me/collections/{id}` `{status:"want"}` | 200，`collected: true` |
| 2 | `DELETE /api/me/collections/{id}`（模拟另一端取消） | 204 |
| 3 | `GET /api/me/collections/{id}` | 200，`collected: false`（**不是 404**，契约规定「未收藏也是 200」） |
| 4 | **`PATCH` `{status:"watched"}`** | **409 `{"code":"COLLECTION_REQUIRED","message":"该作品不在收藏中，请刷新后重试"}`** |
| 5 | `GET /api/me/collections` 复查 | 该作品**不在列表中**——没有被自动重建 |
| 6 | 重新 `PUT` 后再 `PATCH` | 200，`status: watched` —— 反证第 4 步的 409 是条件性的，不是接口坏了 |

**客户端代码路径**（两端都是 `PATCH`，没有任何地方在 409 之后补 `PUT`）：

- 详情页 `work_collection_controller.dart:131-138`：`collectionRequired` → `ref.invalidateSelf()` 重查一次，把错误交回上层提示
- 收藏页 `collection_controller.dart:71-77`：同上，`ref.invalidateSelf()` 让列表与服务端对齐
- 文案 `api_exception.dart:66`：「该作品已不在收藏中，请刷新后重试」
- 数据层 `collection_remote_data_source.dart:92`：只发 `PATCH`，不降级成 `PUT`

**服务端结论：通过（3/3）**——409 正确、不重建、正常路径仍可用。

**端到端实测**（2026-10-22 03:05，模拟器 `Pixel_5_API_35` + 真实后端，`flutter run --dart-define=USE_MOCK=false`）：

| 步骤 | 操作 | 观察到的结果 |
| --- | --- | --- |
| 1 | 手机进 `NHK15个动画短片` 详情页，点「加入收藏」 | 按钮变「已收藏」，出现「修改观看状态 / 未设状态」，SnackBar「已加入收藏」 |
| 2 | **页面不动**，宿主机用同一账号 `DELETE /api/me/collections/{id}` | 服务端 204 → `collected:false`；**手机界面仍停在「已收藏」**（要复现的过期状态出现了） |
| 3 | 手机上打开状态菜单，选「看过」 | SnackBar「**该作品已不在收藏中，请刷新后重试**」 |
| 4 | 同一步之后再界面 | 按钮已从「已收藏」变回「加入收藏」，状态选择器消失（`invalidateSelf()` 重查的结果） |
| 5 | 服务端复查 | `collected:false`，收藏总数仍为 2 —— **没有被重新创建** |

第 3 步的文案与 `api_exception.dart:66` 一致；第 4 步是「不假装成功」的直接证据：界面不是留在错误的「已收藏」，而是退回真实状态。

**判定：通过（端到端）。**

## 验收发现的问题

### 1. 收藏卡在手机宽度下底部溢出（已修）

手机收藏页每张卡片底部都有 `BOTTOM OVERFLOWED BY 7.0 PIXELS` 的黄黑条纹。

原因是卡片正文高度写死 `cardBodyHeight = 112`，而收藏卡比作品库卡片多一行
「观看状态 + 更新时间」：`16(padding) + 40(标题) + 6 + 41(状态 chip) + 16(时间) = 119`，
差 7px 正好对上溢出量。

修法（`fix(client): 收藏卡在手机宽度下溢出`）：

- 新增 `AppLayout.collectionCardBodyHeight = 124`，**不动**作品库卡片用的 112
  （作品库卡片内容刚好装满 112，跟着调高只会在标签行下多一条空白）
- 网格 `mainAxisExtent` 乘 `MediaQuery.textScalerOf(context).scale(1)`：
  用户把系统字体调大时卡片一起变高，否则固定高度还会再撑爆
- 标题从 `SizedBox(height: 40)` 改成 `Expanded`，让标题承接剩余空间

桌面端一直没暴露这个问题，因为窗口宽、卡片也宽，卡片高度相同但文字行高一致——
**这类问题只有在真机尺寸上才看得见**，也是这轮双端验收的主要收获。

### 2. Android 连不上本地后端（联调前置，已加配置）

`android/app/src/main/res/xml/network_security_config.xml` 只放行来源站 `154.8.194.198`，
Android 9+ 对未列出的主机禁止明文 HTTP，模拟器连 `10.0.2.2:8080` 会被直接拦掉。

修法：新增 `android/app/src/debug/res/xml/network_security_config.xml`（只对 debug 变体生效），
按名单放行 `10.0.2.2` / `localhost` / `127.0.0.1` 与来源站。

**没有**开 `base-config cleartextTrafficPermitted="true"`：那等于对所有主机放行，
debug 包虽不发版，但一旦被拿去安全扫描，结论会很难解释。

## 没覆盖到的

- **弱网与断网恢复**：只测了「完全阻断 → 超时」，没测「断网恢复后自动重试」。

- **封面在移动端的解码开销**：`CoverImage` 还没传 `memCacheWidth`，列表封面按原图解码。
