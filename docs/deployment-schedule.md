# 部署排期（接单后 3 天上线 + 接单前能力预建 + 完整成熟度里程碑）

> 状态：排期草案（2026-10-26 负责人拍板目标：**接单后 3 天完成新站部署，第 3 天用户可用 App**）
> 上位依据：[`deployment-requirement.md`](deployment-requirement.md)（部署能力分级与验收口径，3 天目标已锁定）

## 0. 目标锁定

- **接单后 3 天完成新站部署**；**第 3 天用户即可用 App**（测试轨道 / 内部分发；公开商店上架的审核周期属外部，不计入 3 天）。
- 3 天是「接单执行窗口」，计时起点 = 合同确认 + 服务器分配到位 + 来源站授权/数据出口可达。外部采购周期不计入，但为交付前置门。
- **前提**：接单前 L2 部署能力必须预建完成，否则 3 天做不到。本排期 §1 即预建项。

## 2. 接单执行窗口（3 天，per site，L2 建成后）

- **Day 1**：分配实例 + 域名解析 + HTTPS 证书 + 基础环境 → `compose up -d --build` → 导入作品快照/首跑同步 → 行数核对（D-1/D-2/D-3/D-4）。
- **Day 2**：按站烘焙客户端（品牌/包名/主题）→ 构建 → 发**测试轨道/内部分发**（D-5）；来源站授权联调（D-6，可与 Day 1 重叠）。
- **Day 3**：外网验收（手机流量逐条验列表/详情/封面/登录/收藏跨端）→ 单站验收清单签字（D-9）→ 备份+监控确认（D-7/D-8）→ **用户当日可装可用**；公开商店上架走审核（外部）。
