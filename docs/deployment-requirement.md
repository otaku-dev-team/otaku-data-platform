## 0. 一句话

"成熟 = B 模式达标 + 真能服务多站"的定义下，**部署能力是一条独立硬指标**：它衡量"把可运行的系统立起来并交付"的速度，与 B/UGC 功能是否建完正交。当前为 **L0（无任何生产能力）**，必须先建成 L2 才有资格对外承诺"几天上线"。

## 2. 部署能力分级（L0–L3）

> 每级必须"真具备"才能对外宣称，禁止把规划当能力。

| 级 | 名称 | 必须真具备的能力 | 当前状态 |
|---|---|---|---|
| **L0** | 无能力 | 只在开发机跑，无公网、无 HTTPS、无备份、无监控 | 已被 L1 取代（2026-10-27） |
| **L1** | 手工可部署 | `deploy-production.md` 四步可执行：配 `.env` → `compose up` → 导数据 → 客户端加 `--dart-define` 重打包；§3 六项配置不踩坑 | ✅ 2026-10-27 在生产机跑通（联调形态：IP + HTTP，无 Nginx）；**数据仍是样例**，全量导入未演练 |
| **L2** | 模板化/半自动 | 每站一份 env 模板 + 一键起栈；按站烘焙客户端脚本（`--site`）；备份/HTTPS 有可复用配置；单站验收清单模板 | **均未建**（§9.1 选项 1 已选，约束未落地） |
| **L3** | 自动化接入 | 接单后编排：分配实例→域名/证书→起栈→导入/同步→烘焙发布→验收，可脚本串联；适配包发布与核心发版解耦、独立回滚 | **未建** |

**升级前置（达成 L2 必须先做）**：买/到位服务器、Nginx+HTTPS、备份自动化、监控、按站烘焙链、单站部署单元 + 适配包剥离 CI（§9.1 约束④）。这些目前全是 `待建`。

## 3. 竞争力目标（具体天数）—— 待拍板

### 3.1 时钟起点（必须写清，否则"几天"无基准）

> "接单后几天"的计时**从以下三项全部就绪开始**，否则是商务/采购周期不是我们的部署周期：
> 1. 合同/PO 确认；
> 2. 可用服务器已分配给我们（持续服务模式）或客户环境已交付（私有化模式）；
> 3. 来源站授权端点 / 只读数据出口确认可达。

服务器采购审批、客户环境准备等**外部周期不计入我们的天数**，但作为交付前置门。

### 3.2 目标（2026-10-26 负责人拍板：锁定 3 天）

| 范围 | 竞争力承诺（建议） | 达标所需能力级 |
|---|---|---|
| **标准单站 · A 模式**（读+收藏+离线+发现，无 UGC） | **≤ 3 个工作日**完成 D-1~D-9 上线验收 | 需先建成 **L2** |
| 冲刺目标（同范围） | **≤ 1 个工作日**（脚本串联后） | 需建成 **L3** |
| **标准单站 · B 模式**（含 UGC+站主后台+运营体系） | 因 UGC/后台先决功能未建，以"**功能就绪后 ≤ 1 周**"为内部目标，**不对外承诺几天** | 需 B 功能 + L2 同时就绪 |
| **第二站起（多站）** | 复用同一套能力，边际上线时间 ≈ 单站；但首个第二站需先收尾 W4（真适配器进 sync + 烘焙链），预计**额外一次性 1–2 周工程** | W4 收尾 + L2 |

### 3.3 3 天目标的逐日拆解（A 模式，L2 建成后）

> 假设服务器+来源站授权已就绪，单站标准接入。

- **Day 1**：分配实例 + 域名解析 + HTTPS 证书 + 基础环境（Docker/防火墙/时区）→ `compose up -d --build` → 导入数据或首跑同步 → 行数核对（D-1/D-2/D-3/D-4）。
- **Day 2**：按站烘焙客户端（品牌/包名/主题）→ 构建 → 发测试轨道（D-5）；来源站授权联调（D-6，可与 Day1 重叠）。
- **Day 3**：外网验收（手机流量逐条验列表/详情/封面/登录/收藏跨端）→ 单站验收清单签字（D-9）→ 备份+监控确认（D-7/D-8）→ 交付。

## 4. 多站语境下的部署要求（与 §9.1 对齐）

- 单站独立部署单元：一个站点一个部署单元，站间互不影响（定位产品要求 1）。
- 适配包发布与核心发版解耦：L1/多数 L2 = 适配包更新，不走核心发版。
- 适配包独立回滚：某站某功能出问题，回滚该站适配包，不动核心、不波及他站。
- 每站一套验收清单（D-9），验收通过才进生产。
- 私有化交付最小集合见 §9.1：交付单站运行态，不交付多站能力/底座平台能力。
