# Otaku Data Platform
面向 ACGN（动画、漫画、游戏、轻小说等）领域的通用数据与内容服务平台，采用 Flutter、Java Spring Boot、Python 和 MySQL 构建。

## 1. 项目目标
建设一个可复用的 ACGN 数据与内容服务平台，为多个独立运营的网站提供通用服务能力。
第一阶段以打通完整的数据链路为目标：
**数据获取与清洗 → 后端接收与存储 → API 查询 → Flutter 客户端展示。**
优先完成可运行、可验证的核心流程，再根据实际进度和需求逐步扩展功能。

## 2. 项目定位
本项目是一个服务于多个独立网站的通用平台，不是将多个网站合并成一个业务系统。
- **Otaku 是首个服务对象。** Otaku 保持独立运营，新平台根据实际需求通过 API、适配器或数据同步等方式为其提供服务。
- **后续网站可以独立接入。** 各网站可以保留自己的产品形态、业务逻辑和运营方式。
- **平台复用通用能力。** 不要求所有网站采用相同的前端、业务流程或用户体系。
- **数据边界保持清晰。** 不默认共享不同网站的账号、收藏、浏览历史等用户数据。具体共享需求需要另行明确。
新平台与 Otaku 可以长期并行运行，不以合并或迁移 Otaku 为项目目标。

## 3. 技术栈与模块分工
| 模块 | 技术 | 主要职责 |
| --- | --- | --- |
| 客户端 | Flutter | 页面展示与用户交互，通过 API 获取数据 |
| 后端 | Java / Spring Boot | 后端接口、业务处理与数据持久化 |
| 数据服务 | Python | 数据获取、清洗、转换与提交 |
| 数据库 | MySQL | 数据存储 |

团队目前按三人协作，分别负责 Flutter、Java 后端和 Python 数据服务。
各模块负责人可以自主决定模块内部的实现方式。涉及模块之间的接口、数据结构或依赖关系时，需要与相关成员协商一致。

## 4. 第一阶段共同目标
第一阶段至少完成以下流程：
1. Python 从至少一个符合使用条件的数据源获取并处理作品数据。
2. Python 将处理后的数据提交给 Java 后端。
3. Java 后端完成必要的数据校验与 MySQL 持久化。
4. Java 后端提供作品列表和详情等查询 API。
5. Flutter 客户端调用真实 API，展示作品列表和详情。
6. 完成必要的联调与验证，并确保团队成员能够了解各模块的运行方式。
各模块可以并行开发。后端和数据服务尚未完成时，客户端可以使用模拟数据推进工作；后端也可以使用测试数据独立开发和验证。
模拟数据用于前期开发，不能代替第一阶段真实数据链路的验收。

## 5. 协作原则
### 5.1 自主实现
各模块负责人自主安排模块内部的设计、编码、目录结构、开发工具和实现步骤。
本 README 只规定项目共同目标、技术边界和协作要求，不限制成员在自己负责的模块内作出合理的技术决策。

### 5.2 接口协商
不同模块需要协作时，相关负责人应共同明确必要的接口约定，包括数据字段、请求与响应格式，以及必要的错误处理规则。
接口一旦被其他模块依赖，涉及变更时应及时通知相关成员，避免各自按照不同约定开发。

### 5.3 及时同步
开发过程中遇到跨模块依赖、接口冲突或影响整体进度的问题，应及时与相关成员沟通。
完成可供其他模块调用的功能后，应提供必要的使用方式、验证结果或联调信息。

### 5.4 尊重独立网站边界
对接 Otaku 或其他网站时，应明确需要复用的能力和数据范围。不得默认需要合并网站、迁移全部业务或共享用户数据。

### 5.5 数据合规
使用外部数据源时，应遵守相关使用条款、访问限制及适用法律法规。不要将密钥、密码等敏感凭据提交到公开仓库。

### 5.6 协作文件边界
不擅自删改其他协作者提交或负责的文件。如确需变更涉及他人模块的接口、数据结构或相关文件，应事先与相关协作者协商一致。

## 7. 完成标准
第一阶段以实际运行结果为准。
核心数据链路应能够打通：数据可以被获取和处理，经过 Java 后端写入 MySQL，再通过查询 API 供 Flutter 客户端展示。
完成相关工作时，应确保必要的接口信息、运行方式和验证结果能够交接给其他成员。
具体功能的实现细节和模块内部验收方式，由对应负责人结合项目目标自行确定；涉及整体集成的事项，由相关成员共同确认。
